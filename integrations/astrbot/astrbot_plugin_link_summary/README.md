# Link Summary

`link_summary` 自动总结 QQ 消息中的公开网页链接和明确的合并转发内容。1.0.13 补齐手机端 QQ 暴露为 `app` / `appmessage` 等明确富卡片组件的 B 站小程序分享，并把文字摘要与已校验封面放进同一条 AstrBot 消息链。1.0.12 的引用/转发语义修正、B 站语义链接与裸 `BV...` / `av...` 识别、无状态公开 GET 瞬态短重试，以及更早版本的知乎退避、provider 回退、LLM 质量门禁、转发视觉链和“必回”契约保持不变。普通聊天、普通引用图片、普通单图/附件、未知结构、显式 WebAE 路由和进入插件前已经停止的事件仍保持原行为；群里不会发送“暂不支持该链接类型”等错误提示。

## 通用网页

普通 `http(s)` 网页统一走安全抓取和轻量 DOM 语义清洗：

1. 每一跳都重新校验 URL、端口、DNS 结果、响应 MIME、解压后体积和重定向次数；
2. 不执行 JavaScript，只解析公开返回的 HTML/XHTML/纯文本；
3. 去除脚本、样式、导航、页眉页脚、侧栏、表单、隐藏节点、广告、评论、推荐、分享、登录弹窗等常见噪音；
4. 优先保留 `article` / `main` 正文，短应用壳会回退到清洗后的 `body`，并去重重复长段落；
5. 标题、描述和清洗正文共用 `max_page_chars` 总字符预算（默认 8000），再作为不可信 JSON 交给当前会话 provider 总结；当前会话 provider 本来不存在时仍使用已配置默认 provider，已存在却选择/调用失败或返回空文本时，仅普通网页/知乎可尝试一次按对象去重后的默认 provider；
6. 网页输出默认限制为 1200 字符，并检查空响应、连续照抄、近似拼接原文和明显缺乏压缩；首次不合格会用更严格的改写提示重试一次，第二次仍不合格时只发送中性链接兜底，绝不回显正文；
7. 无状态公开 GET 只对传输错误、HTTP 408/425/429 和 5xx 使用全新客户端短重试一次，等待 0.35 秒；403、错误 MIME、超限响应、不安全目标和越界重定向不重试，每次尝试和每个重定向仍重新执行 URL、DNS 与 SSRF 校验。

这条管线适用于各种返回公开可读 HTML 的网站，而不是只支持某一个站点。站点若在普通页面入口阻断公开抓取，可以增加“精确域名 + 精确公开内容路径”的无凭据适配器，并继续复用同一套 DOM 清洗和总预算。1.0.6 首个适配器是知乎公开回答页；它只读取回答正文、摘录和问题标题，不读取作者、UID、头像等身份字段。

需要登录、验证码、付费墙或只靠浏览器 JavaScript 动态生成正文的网站不会尝试绕过限制；链接已经被识别但无法取得足够公开内容时，只回复“暂时无法生成可靠摘要”的中性结果。

## B 站视频

支持 `www.bilibili.com/video/...`、`m.bilibili.com/video/...`、`b23.tv` 短链，以及 Plain/Reply/Forward 可见文本中的独立 `BV...`、`av...`。手机端 QQ 的 `app` / `appmessage` 和适配器明确标记的 `ark` / `miniapp` 富卡片与既有 JSON/XML 小程序分享共用受限解析，只读取 `meta.detail_1.qqdocurl`、`meta.news.jumpUrl` 等语义导航字段；`preview`、`icon`、`cover`、头像、附件和未知媒体字段不会成为目标链接。短链关闭自动跳转并逐跳校验，只允许留在精确的 B 站短链/视频域。成功时输出：

- 标题、UP 主、简介、播放量、评论数、点赞数、发布时间和时长；
- 经 MIME、大小和文件签名校验后下载的 JPEG/PNG/WebP 封面字节；文字摘要与封面以一条 `Plain + Image.fromBytes()` AstrBot 消息链发送；
- 有界公开热评的匿名归纳“网友怎么说”。

热评只把正文和点赞数送入模型，不读取或保存评论昵称、UID、头像。评论接口失败只降级热评部分，不影响已取得的视频元数据。封面下载或消息链构造失败时只发送文字摘要；远程 B 站 CDN URL 不会交给 OneBot/NapCat 二次下载。

## QQ 消息与合并转发

链接提取支持 Plain/Text、Share、QQ JSON/XML 与明确的 `app` / `appmessage` / `ark` / `miniapp` 分享卡片、Reply、Node/Nodes、OneBot `get_msg` / `get_forward_msg` 和 QQ Official 明确暴露的引用或嵌套消息结构。QQ Official 的 `message_type=103` 明确是引用回复，不是合并转发：优先读取 `Reply.chain` / `message_str` / `text` 和平台已经暴露的引用正文；只有 Reply 仍只有目标 ID 时，才在最多四次回取的总上限内调用 `get_msg`，失败只记录匿名异常类型。如果回取结果本身含有真实 Forward，再使用 `get_forward_msg` 展开。只有显式 Forward/Node/Nodes 才会进入合并转发文字/图片视觉链。只处理第一条用户可见导航链接；图片 CDN、附件、文件、语音、视频、头像、封面和预览字段不会被误当作网页链接。

明确的合并转发即使没有链接也会总结：

- 纯文字：总结转发中的可见文字；
- 图文混合：显式 Image 组件先复用 Private Companion 已配置的转发图片视觉链，再把有界视觉摘要与可见文字交给当前会话 provider；
- 全图片：复用同一条视觉链识别并压缩每张图；普通文本摘要 provider 不可用时，仍直接返回已经取得的有界视觉摘要。

合并转发中真实可见的网页链接在没有转发图片时仍优先执行链接摘要；QQ 外层平台导航 URL 不会抢过已经识别出的转发图片。视觉桥只定位已加载的 Private Companion 实例并调用它现有的 `PLUGIN_VISION_PROVIDER_ID` 候选、图片准备、GIF 抽帧、缓存、失败冷却和预算策略，不读取 provider 配置，不新增模型 ID、API 地址或凭据。共享视觉链不可用时，仍保留当前会话 provider 的 `image_urls` 兼容路径；两条视觉路径均不可用或平台未暴露图片时才回复中性兜底，不会伪称看过不可见内容。普通单图、普通附件和没有明确合并转发标记的媒体消息不触发本插件。转发解析有递归深度、节点数、文本块数、文本总长度、图片数和图片 URL 长度硬上限；不会传递昵称、QQ 号、UID、头像、附件或未知媒体字段，也不会记录正文、图片 URL、转发 ID 或卡片 JSON。

消息处理优先级为 99：低于 `textech_intent` 的 100，让显式 WebAE 所有权先完成裁决；高于可能与插件竞争的 90 级普通群聊处理器。只有本插件生成正常摘要或中性兜底后才关闭默认 LLM 并停止事件。

## 安全边界

- 不使用 Cookie、Authorization、用户会话、验证码、登录绕过或系统代理；
- 不启动浏览器/Playwright，不把群成员发送的 URL 转交公共 Reader SaaS；
- 只允许 80/443，拒绝 userinfo、回环、私网、链路本地、保留地址和云元数据地址；
- 网页、评论、转发文字和图片都被标记为不可信输入，模型不得执行其中的命令或继续访问其中链接；
- 日志只记录匿名生命周期标签和异常类型，不记录完整 URL、query、网页正文、评论、引用/转发正文、Reply/Forward ID、图片 URL 或响应体。

## 配置

常用配置见 `_conf_schema.json`：

- `request_timeout_seconds`、`max_redirects`、`max_download_bytes`
- `max_page_chars`（标题、描述、DOM 清洗正文的总字符预算，默认 8000）
- `max_page_summary_chars`（网页 LLM 提炼结果的字符上限，默认 1200）
- `max_comments`
- `llm_timeout_seconds`、`llm_max_tokens`、`max_summary_chars`
- `max_reply_chars`、`max_concurrency`
- `send_bilibili_cover`

- 1.0.12：修正把 QQ Official `message_type=103` 引用误判为合并转发的问题；支持结构化 Reply 与 QQ Official ID-only 引用的有界 `get_msg` 回取、引用中真实 Forward 的继续展开、QQ/B 站小程序语义链接、Plain/Reply/Forward 可见文本中的裸 BV/av；公开 GET 仅在传输错误、408/425/429/5xx 时使用全新无状态客户端短重试一次，永久状态、MIME/体积/安全校验失败不重试。真正 Forward/Node/Nodes 的文字与显式图片视觉链保持不变。
- 1.0.11：知乎精确公开 JSON GET 在 FetchError 后最多重试两次，重试前依次等待 0.35 秒、1.0 秒；不在首次请求前或第三次失败后等待。1.0.10 的普通网页/知乎群会话 provider 选择、调用或空响应失败时的去重默认 provider 回退保持不变，额外切换不用于 B 站或合并转发，且不扫描任意 provider。

- 1.0.6：通用 DOM 语义清洗和总输入预算；知乎公开回答适配；无链接、图文及全图片合并转发摘要。
- 1.0.5：公共通用网页使用固定浏览器兼容请求头，仍保持无凭据和无代理继承。
