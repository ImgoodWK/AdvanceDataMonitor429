## 0. 快速了解

**TeXTech** 是 GTNH 整合包环境下的 Minecraft 1.7.10 工具模组，为 AE2 网络提供数据监控、可视化与 AI 辅助。

| 能力 | 说明 |
|------|------|
| 高级数据监视器 | 折线图、柱状图等多种图表，实时显示绑定目标数据 |
| AE2 链接器 | 高级网络链接器（三合一：网络统计 + 存储元件槽 + 合成 CPU）接入 AE2 |
| 挂索移动 | 沿索道路网平滑滑行，双手自由操作 |
| AI 助手 | 自然语言查询 AE2、合成下单、取出物品、计划管理 |
| 语音助手 | V 键录音，Vosk 离线或 HTTP STT |
| WebAE 控制台 | 浏览器管理 AE2/GT（默认关闭；详见 [WebAE 用户手册](../webae/用户手册.md)） |

**主要方块与物品**（游戏内显示名，详见 [开发者技术文档 §5](../developer/技术文档.md#5-方块物品与-tileentity)）：高级数据监视器、数据映录器、高级网络链接器、物质球解压器、挂索节点、挂索器、高级存储链接元件、数据织尘/织形/涌流/织潮/织源元件、编织增幅卡、高级计划器、超能砂糖桔、至高天圣裁、铽丝科技手册、次元口袋（含空间/翻页升级卡）等。

**适用环境**：GTNH 或包含 AE2/GTNH 依赖的 1.7.10 整合包。安装后编辑 `config/textech/textech.cfg` 配置 AI Key 即可启用助手功能。

# TeXTech 模组详细介绍与使用教程


本文档面向玩家、整合包作者和服务器管理员，介绍 `铽丝科技`（TeXTech）模组的功能、安装、使用流程、AI 助手、语音助手、配置文件和常见问题。

当前代码目标环境为 Minecraft `1.7.10`，Forge `10.13.4.1614`，项目使用 GTNH Convention Gradle 构建。模组 ID 为 `textech`。

## 1. 模组定位

`铽丝科技` 是一个以“世界内可视化数据面板 + AE2 网络监控 + AI 助手”为核心的工具模组。它可以把机器、AE2 网络、AE2 合成 CPU、AE2 存储项目等数据采集出来，在游戏世界中渲染成图表、文字或物品数量展示，并提供一个 AI 对话窗口，让玩家用自然语言查询 AE2 存储、查看样板、提交合成订单、批量下单和管理简单计划。

模组目前主要包含以下能力：

- 高级数据监视器方块：在世界中显示图表、标题、文字、AE2 存储项和合成状态。
- 数据映录器：绑定方块并查看目标 TileEntity 的 NBT，辅助找出可监控字段。
- 高级网络链接器方块：三合一 AE2 连接器，汇总网络存储统计、按高级存储链接元件显示库存、监控合成 CPU；右键开存储 GUI，Shift+右键聊天综合状态。
- AI 对话与助手：支持 OpenAI-compatible Chat API，既可普通聊天，也可转换自然语言为 AE2 查询、合成操作和取出物品到背包。
- 语音助手：默认 Windows 离线 Vosk；也可录音后调用 OpenAI-compatible HTTP STT，再进入同一 AI 助手流程。
- 挂索节点与挂索器：在基地与产线之间沿索道路网平滑滑行，双手可自由操作，让移动过程本身成为观赏与探索的一部分（详见第 3.7、3.8 节）。
- 命令与配置：提供 `/admai`、`/admassistant` 等命令和 Forge config 文件。

## 2. 环境与安装

### 2.1 运行环境

代码中标明的目标版本如下：

- Minecraft：`1.7.10`
- Minecraft Forge：`10.13.4.1614`
- Mod ID：`textech`
- Mod 名称：`铽丝科技`
- Java 运行目标：JVM 8；项目本身通过 Jabel 允许使用部分现代 Java 语法。

### 2.2 依赖说明

从代码使用的 API 可以看出，本模组依赖或面向以下环境：

- Forge 1.7.10。
- Applied Energistics 2（AE2），因为多个链接器方块继承/使用 AE2 网络 API。
- GTNH 相关开发环境与依赖集合。
- 流体统计部分使用了 ExtraCells/AE Fluid 相关 API（如 `FluidCellInventoryHandler`、`IFluidCellInventory`）。
- 部分 NBT 辅助支持 GregTech TileEntity 名称读取。

如果安装到普通客户端或服务器，建议放在 GTNH 或包含 AE2/GTNH 相关依赖的 1.7.10 整合包中使用。

### 2.3 安装步骤

1. 确认客户端和服务器都安装 Forge 1.7.10。
2. 将编译好的 `铽丝科技` jar 放入客户端与服务器的 `mods/` 目录。
3. 确保 AE2、GTNH/相关依赖已经存在。
4. 启动一次游戏或服务器，让 Forge 生成配置文件。
5. 如果要使用 AI 或语音功能，编辑配置文件或在游戏内设置 API Key。

### 2.4 配方说明

模组通过 `LoaderRecipe` 注册 **GTNH Assembler（IV）** 与 **装配线（UHV）** 配方（需 GregTech）。已有配方的包括：

| 注册名 | 显示名 | 机器 |
|--------|--------|------|
| `advDataMonitor` | 高级数据监视器 | Assembler IV |
| `advNetworkLinkBlock` | 高级网络链接器（三合一） | Assembler IV |
| `data_imprint` | 数据映录器 | Assembler IV |
| `advance_storage_link_cell` | 高级存储链接元件（一次出 2） | Assembler IV |
| `advance_planner` | 高级计划器 | Assembler IV |
| `advance_link_scanner` | 高级链接扫描器 | Assembler IV |
| `dimensional_pocket` | 次元口袋 | Assembler IV |
| `space_upgrade_card` | 空间升级卡（一次出 4） | Assembler IV |
| `page_upgrade_card` | 翻页升级卡（一次出 2） | Assembler IV |
| `matterBallDecompressor` | 物质球解压器 | UHV 装配线（研究物品：高级网络链接器） |

以下物品/方块**当前无内置配方**，需创造模式、NEI Give、或整合包 CraftTweaker 补充：

- `grappleAnchor` / `grapple_hook`：挂索节点 / 挂索器
- 数据编织元件与增幅卡（织尘/织形/涌流/织潮/织源、编织增幅卡、超级编织增幅卡）
- `stack_upgrade_card` / `infinite_stack_upgrade_card`：堆叠 / 无尽堆叠升级卡
- 星空剑、至高天圣裁、超能砂糖桔等特殊物品
- 手册物品本身（每位玩家每世界首次进入会获赠）

## 3. 物品与方块总览

### 3.1 高级数据监视器

注册名：`textech:advDataMonitor`

用途：主显示方块。玩家右键打开主界面，可以添加数据绑定、切换显示方向、隐藏/显示外壳或屏幕、打开 AI 对话界面。数据会保存在方块 TileEntity NBT 中，并同步给客户端渲染。

特点：

- 放置时自动记录自身坐标作为默认绑定目标。
- 默认启用一个“演示模式”显示项，采集 `testRandomData`。
- 支持多个显示项，每个显示项拥有独立坐标、数据字段、图表样式、采样间隔和渲染变换。
- 每个监视器面最多 **36** 条数据绑定（`MAX_DATA_BINDINGS`）；单条绑定的图表数据点数（`dataLimit`）默认仍为 100。
- 可渲染折线图、柱状图、3D 柱状图、瀑布流、势差图、合成监控文本和存储物品列表。
- 主界面提供 AI 按钮，用于打开 AI 对话。

### 3.2 数据映录器

注册名：`textech:data_imprint`

用途：映录目标方块 NBT 快照并绑定到数据监视器，帮助玩家找到可监控字段名；也可记录附近 GT 机器坐标并批量绑定。只观测与记录，不会编织物质（编织功能见数据织尘/织形/涌流/织源元件；织尘/织形/涌流不可标记本模组物品）。

**互斥载荷**：工具上同一时刻只保留一种数据——「方块映录」（`boundPos`）或「GT 机器列表」（`gtMachineList`）。写入一侧会自动清除另一侧并聊天提示。

使用方法：

- 潜行右键非监视器方块（非 GT）：映录该方块坐标与 TileEntity NBT；若已有 GT 列表则清除。
- 潜行右键 GT 机器：将机器坐标加入 GT 列表；若已有方块映录则清除。
- 潜行右键高级数据监视器：按当前唯一载荷绑定（GT 列表 → 批量绑 GT；方块映录 → 添加图表绑定槽）。
- 普通右键空气：若已映录方块 TileEntity，打开 NBT 查看界面；若仅有 GT 列表则提示数量。
- 潜行右键空气：工具上**有载荷**时清除全部数据；**无载荷**时按当前扫描半径批量扫描附近 GT 机器。
- 潜行 + 滚轮：切换 GT 扫描半径（8 / 16 / 32 / 64）。

注意事项：

- 不能把高级数据监视器自身当作映录目标。
- 潜行 + 右键监视器添加方块绑定时，若当前面已有 36 条绑定，会提示 `adm.error.data_bindings_full` 且不会新增。
- 方块绑定存的是当时的 TileEntity NBT 快照，不一定实时刷新。
- 如果目标方块没有 TileEntity 或没有 NBT，打开查看器时会提示无数据。
- 旧版物品若同时带有两套载荷，首次绑监视器时会保留 GT 列表并清除冲突的方块映录（有聊天提示）。

### 3.3 高级网络链接器

注册名：`textech:advNetworkLinkBlock`

用途：三合一 AE2 连接器，将原网络链接器、高级存储链接器、合成链接器合并为单一方块。接入 AE2 网络后同时提供：全网物品/流体存储统计、按高级存储链接元件分区显示库存、合成 CPU 状态监控，并作为 AI 助手查询/合成/取物的附近链接器入口。

特点：

- 是 AE 网络 TileEntity，会请求 AE2 频道；使用 Smart Cable 连接类型。
- 每 20 tick 自动刷新网络统计、标记物品数量与合成 CPU 数据。
- **右键**打开存储配置 GUI（36 个槽位，仅接受高级存储链接元件）。
- **Shift+右键**在聊天栏输出综合状态（网络字节/类型 + 合成 CPU 摘要）。
- 绑定到高级数据监视器时，按 `dataType` 选择显示类型：网络图表（`line`）、存储图标（`storage`）、合成文字（`crafting`）。

**网络统计指标**（绑定监视器后可选）：

- `ItemTotalBytes` / `ItemUsedBytes` / `ItemTotalTypes` / `ItemUsedTypes`
- `FluidTotalBytes` / `FluidUsedBytes` / `FluidTotalTypes` / `FluidUsedTypes`

**合成 CPU 指标**（`dataType=crafting`）：

- 全局：`totalCpus`、`busyCpus`、`cpuTotalBytes`、`cpuUsedBytes`、`totalCoProcessors`
- 单 CPU：`busyCpus:CPU#1`、`usedStorage:CPU#1`、`finalOutputName:CPU#1` 等（名称须与 AE2 中一致）

**存储显示**（`dataType=storage`）：

1. 在 AE2 Cell Workbench 配置高级存储链接元件分区（可选 Fuzzy / Inverter / Ore Filter / 流体标记）。
2. 将元件放入链接器 GUI 的 36 个槽位之一。
3. 在监视器绑定该方块坐标，选择存储显示配置（列数、图标大小、数量/进出/名称开关等）。
4. **数据编织元件**（织尘/织形/涌流/织源）内部存量**不计入**存储统计。

### 3.4 高级存储链接元件

注册名：`textech:advance_storage_link_cell`

用途：不是实际存储单元，而是高级网络链接器的“过滤/标记配置单元”。

特点：

- 最大堆叠 1。
- 实现 AE2 `ICellWorkbenchItem`，可以放入 AE2 Cell Workbench 编辑配置。
- 有 2 个升级槽。
- 允许安装 AE2 Fuzzy Card、Inverter Card 和 Ore Filter Card。
- 分区配置槽中的物品决定高级网络链接器显示哪些物品。
- 支持 NBT 流体标记（`fluidMarkers`），可存储流体目标以监控 AE2 流体存量。
- **不统计数据编织元件**：织尘/织形/涌流/织源元件内部 `dataLoomItemAccum` / `dataLoomFluidAccum` 存量不计入高级网络链接器存储显示。

### 3.5 挂索节点

注册名：`textech:grappleAnchor`

**设计初衷**：我们往往把建筑与产线做得十分漂亮，日常却习惯飞行、跑步或直接传送——飞行和跑步占用手键，传送则让沿途风景一闪而过。挂索节点与挂索器希望在「快到达」与「看见路上」之间找到平衡：在值得慢慢看的路径上布置节点，用滑行代替「瞬移路过」。

用途：可贴 6 面放置的薄板锚点，与挂索器配合构成基地内的索道路网。

使用方法：

- 贴在墙、顶或地的 solid 面上放置（像嵌入建筑的薄板）。
- 手持挂索器靠近节点：12 格内出现文字提示，6 格内显示世界空间导航图标。
- 磁吸选中节点（图标变绿放大）后**右键**挂接；挂接后定身，可自由转动视角。
- 挂接状态下，可达范围内的其他节点以图标显示（**穿墙可见**）；磁吸选中目标后**右键**沿直线平滑滑行。
- **Shift** 取消挂接。
- **Shift + 右键**节点：打开节点配置（显示名称、选中图标颜色）。

建议布点：产线参观动线、景观连桥、多层工厂竖向通道、基地大门到核心区域的主路径。

配置：Forge 配置 `[grapple]` 分类（提示范围、交互距离、扫描半径、滑行速度、磁吸角度等）。详见 [挂索节点系统设计](../subsystems/挂索节点系统设计.md)。

### 3.6 挂索器

注册名：`textech:grapple_hook`

用途：与挂索节点互动的核心工具。堆叠数 1。

特点：

- 靠近节点时 HUD 提示；磁吸选点无需精准瞄准（视角锥 + 屏幕像素双模式）。
- 挂接后双手仍可自由操作，适合在滑行途中使用背包与工具。
- **Shift + 右键**打开挂索器设置：滑行速度、是否显示节点名称与距离。

与传送/飞行的关系：挂索系统不替代 AE2 传送或飞行模组，而是为「值得欣赏的路径」提供一种更有过程感、又不占双手的通行方式。
### 3.7 数据编织元件

数据编织元件是 AE2 存储单元，放入 ME 驱动器或 ME 箱子后，按工作台标记的目标**从 AE 网络数据中编织**出物品、流体或源质（与映录器「只观测不编织」不同）。

| 元件 | 注册名前缀 | 通道 | 标记限制 |
|------|-----------|------|----------|
| 数据织尘元件 | `data_dust_loom_cell` | 物品 | 仅 GT 粉类；不可标记本模组物品 |
| 数据织形元件 | `data_form_loom_cell` | 物品 | 任意物品；不可标记本模组物品 |
| 数据涌流元件 | `data_flow_cell` | 流体 | 任意流体；5 种类 |
| 数据织潮元件 | `data_tide_loom_cell` | 流体 | 同涌流；63 种类；附魔光效 |
| 数据织源元件 | `data_source_loom_cell` | 流体 | 仅 Thaumcraft 源质 aspect 流体 |

**编织增幅卡**（普通 4×/张、超级 16×/张，可叠乘，最多 8 张）可插入元件升级槽加速产出。元件内部累积存量**不计入**高级网络链接器存储统计。

配置分节：`[dataDustLoomCell]`、`[dataFormLoomCell]`、`[dataFlowCell]`、`[dataSourceLoomCell]`、`[dataLoomCell]`。详见 [开发者文档 §5.7](../developer/技术文档.md#57-data-loom-cells数据编织元件)。

### 3.8 超能砂糖桔

注册名：`textech:orange`（lang：`item.orange.name`）

传奇物品（lang：`adm.super_orange.tooltip.legendary`）。主要能力：

- **任意方块挖掘**：手持时可瞬间挖掘任意方块（含 GT 矿石）
- **设置 GUI**（潜行 + 右键，lang：`adm.super_orange.tooltip.open_config`）：铭牌文字、挖掘物质球开关、拾取合并开关、丢弃合并开关、自定义掉落倍率（上限见 `[superOrange] dropMultiplierMax`，默认 ×2）
- **无人机与投掷物免疫**：普通右键开关；本体在玩家周围漂浮并拦截投掷物，附近有怪时分身出击
- **头顶铭牌与光环**：设置 GUI 或铁砧重命名可设置铭牌文字；第一人称隐藏自身，第三人称/他人可见

**升级系统**

| 升级卡 | 注册名 | 效果 | 上限 |
|--------|--------|------|------|
| 空间升级卡 | `textech:spaceUpgradeCard` | 每张 +1 槽位（默认 1 格，最多 63 格/页） | 64 张（其中 62 张有效） |
| 翻页升级卡 | `textech:pageUpgradeCard` | 每张 +1 页（最多 9 页） | 8 张，需空间升级装满 64 张后才生效 |
| 堆叠升级卡 | `textech:stackUpgradeCard` | 每张 ×2 单槽堆叠上限（默认 64，最高 65536） | 10 张 |
| 无尽堆叠升级卡 | `textech:infiniteStackUpgradeCard` | 仓库内该物品背包可堆叠，口袋格子不限 | 1 张，需堆叠升级装满足额后才生效 |

**容量公式**：每页格数 = `min(63, 1 + min(空间升级数, 62))`；页数 = 空间满 64 时 `1 + min(翻页升级数, 8)`，否则 1 页。

**已修复问题（2026-06）**

| 问题 | 修复说明 |
|------|----------|
| 重启存档后数量变 1 | **已修复**。根因：`ItemStack.writeToNBT` 将 `stackSize` 强转为 byte 写入，与 GTNH/Forge 的 Int 读取不兼容。改为统一使用 `setInteger("Count")` 显式写入，并在读取时兼容 byte/short/int 三种类型。 |
| 悬浮窗角标显示 0 | **已修复**。根因同数量变 1：`PacketPocketSync` 序列化沿用原版 byte 写入，导致客户端侧 `loadItemStackFromNBT` 读取时 Count 为 0。统一改为 Integer 类型传输后修复。 |

## 4. 高级数据监视器使用教程

### 4.1 基础搭建

1. 放置一个高级数据监视器。
2. 右键打开主界面。
3. 点击“新增绑定”。
4. 输入目标方块坐标 `x,y,z`，保存。
5. 界面会根据目标方块类型打开不同配置页面：普通 TileEntity，或统一高级网络链接器（按 `dataType` 选择网络图表 / 存储显示 / 合成监控）。
6. 设置标题、显示类型、偏移、旋转、缩放、采样间隔等参数。
7. 点击保存后返回主界面，世界中的监视器会开始显示数据。

### 4.2 主界面按钮

- 方向按钮：循环切换显示朝向，支持南/西/北/东。
- 新增绑定：输入坐标并新增一个显示项。
- 添加：新增一个通用显示项入口。
- 隐藏/显示：切换部分显示组件可见性。
- 单面/双面：切换显示面。
- AI：打开 AI 对话窗口。
- 数据项小按钮：每个已有显示项会有对应按钮，可进入该项配置。
- 颜色配置：部分数据项可进入颜色/图表类型配置。

### 4.3 坐标绑定

每个监视器面最多 36 条数据绑定（映录器潜行绑定与 GUI「新增绑定」共用同一上限）。`dataLimit` 控制单条图表保留的数据点数量，默认 100，与绑定条目上限无关。

坐标格式必须是英文逗号分隔的整数：

```text
123,64,-123
```

常见错误包括使用中文逗号、目标方块不存在、目标方块不是 TileEntity。

### 4.4 通用图表配置

通用图表用于监控普通 TileEntity NBT 数值，或一些 AE 方块数值。核心字段如下：

- `XYZ`：目标方块坐标。
- `name`：要读取的 NBT 字段名或 AE 网络指标名。
- `displayName`：图表标题。
- `dataType`：显示类型。
- `dataLimit`：保留/显示的数据点数量。
- `interval`：采样间隔，单位 tick。20 tick 约等于 1 秒。
- `xRange`：X 轴显示长度。
- `yRange`：Y 轴显示高度/范围。
- `yMin`、`yMax`：Y 轴上下限。
- `isValue`：对部分 AE 网络指标可切换为百分比含义。

图表类型：`line` 折线图、`bar` 柱状图、`bar3d` 3D 柱状图、`waterfall` 瀑布流、`diffrence` 势差图、`crafting` 合成监控文本、`storage` 存储物品数量展示。

### 4.5 显示位置、旋转和缩放

每个显示项都有独立的空间变换：

- `xOffset`、`yOffset`、`zOffset`：相对监视器的位置偏移，单位约为方块。
- `rotationX`、`rotationY`、`rotationZ`：三轴旋转角度。
- `scale`：整体缩放。

如果图表看不见，先把 `scale` 调大，例如 `0.5` 或 `1.0`；如果图表嵌进方块，调整 `zOffset` 或 `yOffset`；如果方向不对，先切换主界面方向，再微调 `rotationY`。

### 4.6 颜色和透明度

颜色字段使用 16 进制 RGB，不需要 `#`，例如：

```text
FFFFFF
00FFFF
FF00FF
```

常见字段：`lineColor`、`axisLineColor`、`axisFontColor`、`displayNameColor`、`gridLineColor`。

透明度字段范围通常是 `0.0` 到 `1.0`，例如 `nameAlpha`、`axisLineAlpha`、`axisFontAlpha`、`lineAlpha`、`gridLineAlpha`。

### 4.7 采样间隔与性能

`interval` 是每个显示项的采样间隔，单位 tick。值越小刷新越频繁，服务器和客户端负担越高。

建议快速变化数据用 `20`，普通机器状态用 `40` 到 `100`，长期趋势提高 `interval` 并适当提高 `dataLimit`。不要在服务器上让大量显示项全部使用 `interval=1`。

## 5. AE2 网络监控教程

1. 将高级网络链接器方块连接到 AE2 网络。
2. 确保 AE2 网络有可用频道。
3. Shift+右键链接器，聊天栏应显示网络容量、类型数与合成 CPU 摘要。
4. 在高级数据监视器中新增绑定，坐标填链接器方块坐标。
5. 选择显示类型「网络统计图表」，在 AE 网络数据配置界面选择要显示的指标。
6. 保存后，监视器会以图表形式显示网络变化。

常用示例：

- 物品存储已用百分比：数据名 `ItemUsedBytes`，显示模式选百分比，图表类型选折线图。
- 流体类型占用：数据名 `FluidUsedTypes`，显示模式选数值或百分比。

## 6. AE2 合成监控教程

### 6.1 搭建合成监控绑定

1. 将高级网络链接器方块接入 AE2 网络（与合成 CPU 同一网络）。
2. 确保 AE2 网络有可用频道。
3. Shift+右键链接器，聊天栏应显示 CPU 统计。
4. 在高级数据监视器中新增绑定，坐标填链接器方块坐标。
5. 选择显示类型「合成监控」，进入合成处理器配置界面。
6. 选择“全网络”或“处理器”模式。
7. 设置文字缩放、透明度、对齐、模板等内容。
8. 保存后显示合成 CPU 状态。

### 6.2 全网络模式

全网络模式直接显示链接器的整体统计文本，适合做总览看板。

### 6.3 单处理器/模板模式

模板中支持 `{br}` 换行、`{变量}` 插入值、`{变量:CPU名称}` 读取指定 CPU、`{表达式 ? "成立时显示" : "不成立时显示"}` 条件显示。

示例：

```text
{br}合成监控{br}总数：{totalCpus} 忙碌：{busyCpus}{br}{busyCpus:CPU#1 == 1 ? "§cCPU#1 正在工作" : "§aCPU#1 空闲"} 已用存储：{usedStorage:CPU#1}
```

CPU 名称必须和 AE2 网络中 CPU 的名称完全一致，否则显示可能为 `??` 或空值。

## 7. AE2 存储显示教程

### 7.1 配置高级存储链接元件

1. 打开 AE2 Cell Workbench。
2. 将高级存储链接元件放入工作台。
3. 在分区/配置槽放入要监控的物品，例如铱锭、锡锭、处理器等。
4. 可选：安装 Fuzzy Card，使匹配使用 AE2 模糊模式（损坏值/百分比容差）。
5. 可选：安装 Inverter Card，让该元件显示“除配置项外”的其他网络物品。
6. 可选：安装 Ore Filter Card，在元件工作台中设置矿典名称（如 `ingotIron`），元件将匹配所有同类物品。
7. 可选：写入流体标记 NBT（`fluidMarkers`），监控 AE2 流体网络中指定流体的存量（单位 mB）。
8. 取出元件。

### 7.2 配置高级网络链接器方块

1. 将高级网络链接器方块接入 AE2 网络。
2. 右键打开存储 GUI。
3. 将配置好的高级存储链接元件放入 36 个槽位之一。
4. 方块会根据每个元件的分区配置统计 AE 网络中对应物品数量。

### 7.3 在监视器上显示存储项

1. 右键高级数据监视器。
2. 点击“新增绑定”。
3. 输入高级网络链接器方块坐标。
4. 选择显示类型「存储显示」，进入存储显示配置。
5. 设置标题、位置、旋转、缩放。
6. 设置 `storageColumns`、`storageSpacing`、`storageIconScale` 和数量颜色。
7. 可选择开启/关闭 数量、进出（吞吐量变化）、名称 三种文字显示，先启用的会排在上排。
8. 保存后，监视器会显示元件配置的物品图标与数量。

## 8. AI 对话与助手

### 8.1 功能概览

AI 窗口既支持普通聊天，也支持“助手工具流”。玩家在高级数据监视器主界面点击 `AI` 按钮即可打开。

AI 助手可以查询 AE2 存储、查询 AE2 可合成样板和配方详情、提交 AE2 合成订单、批量提交合成订单、按序号确认候选项、取消当前助手操作或服务端合成任务、创建/列出/完成简单计划、将 AE2 存储中的物品取出到玩家背包以及普通聊天。

### 8.2 AI 可用条件

AI 结构化助手主路径可用需要满足：

- `ai.networkEnabled = true`
- 已配置 `ai.apiKey`，或环境变量 `DEEPSEEK_API_KEY` 不为空。

如果 AI 不可用，助手会退回本地规则解析器。规则解析器能处理部分中文/英文命令，但自然语言理解能力弱于 AI。

### 8.3 隐私提示

AI 对话会把你的输入和最近聊天历史发送给配置的模型供应商。首次使用时需要确认隐私提示。确认状态保存在 `ai.privacyConfirmed=true`。语音助手也有独立的 `voice.privacyConfirmed=true`。

### 8.4 查询 AE2 存储

前提：玩家附近 32 格内需要有高级网络链接器方块。

示例：

```text
查一下 AE 里有多少锡锭
看看流体存储里有多少熔融焊锡
查询所有存储里有没有铱锭
```

存储范围包括：

- `all`：物品和流体都查。
- `items`：只查物品。
- `fluids`：只查流体。

AI 会尽量从自然语言中判断范围，例如“流体”“液体”倾向 `fluids`，“物品”“材料”倾向 `items`。

### 8.5 查询可合成样板

前提：玩家附近 32 格内需要有高级网络链接器方块，且该方块接入有样板的 AE2 网络。

示例：

```text
查询铱板怎么合成
列出 AE 里能合成的处理器
查看第 2 个样板详情
```

如果查询目标为空或很宽泛，助手会返回一组可合成候选项。玩家输入序号后，会查看该候选项的配方详情。

### 8.6 提交合成订单

示例：

```text
帮我合成 64 个锡齿轮
下单 4 个量子处理器
```

流程：

1. 助手搜索 AE2 合成候选项。
2. 如果有多个候选项，会显示序号列表。
3. 玩家输入序号确认。
4. 服务端提交 AE2 合成任务。

单行订单数量受 `assistant.maxOrderAmount` 限制，默认 `4096`。

### 8.7 批量下单

示例：

```text
帮我合成 64 个锡齿轮，32 个铜线，4 个量子处理器
```

确认示例：

```text
确认
继续下单
```

追加示例：

```text
再加 16 个钢板
```

合并示例：

```text
把刚刚的加起来一起下单
```

限制：

- 单次 AI 结构化解析最多处理 8 个任务。
- 批量提交要求每一行都有可用候选项。
- 批量提交前会检查可用 AE2 计算槽数量，如果可用槽少于订单行数，则不会提交任何任务。
- 单行数量仍受 `assistant.maxOrderAmount` 限制。

### 8.8 取出 AE2 物品到背包

不同于"合成下单"（让 AE2 制作新物品），"取出"功能直接从 AE2 存储中转移已有的物品到玩家背包。

前提：玩家附近 32 格内需要有高级网络链接器方块。

示例：

```text
取出 64 个锡锭到背包
从 AE 里拿 32 个铜板
给我 16 个铱锭
```

流程：

1. 助手搜索 AE2 存储网络中的匹配物品。
2. 如果有多个候选项，会显示序号列表。
3. 玩家输入序号确认。
4. 服务端从 AE2 存储中将物品取出并转入玩家背包。

单次取出数量受 `assistant.maxWithdrawAmount` 限制，默认 `4096`。

**部分取出确认**：当玩家背包空间不足以容纳请求的全部数量时，助手会提示"背包最多还能放 X 个，是否取出 X 个？"。玩家输入"确认"后，助手会取出背包能容纳的数量。

### 8.9 批量取出物品

示例：

```text
取出 64 个锡锭，32 个铜板，16 个铱锭
从 AE 仓库给我拿 64 个红石和 32 个萤石粉
```

流程与批量合成下单类似：

1. AI 结构化解析为多个取出任务。
2. 服务端逐一搜索候选项。
3. 玩家确认后，服务端逐行执行取出操作。

批量取出的限制：

- 单次 AI 解析最多 8 个任务。
- 某一行背包空间不足时，批量操作会暂停并提示玩家先单项确认。
- 某一行失败时，后续行不会继续取出。
- 单行数量受 `assistant.maxWithdrawAmount` 限制。

追加和合并操作（"再加 X 个""把刚刚的合并取出"）同样支持。

### 8.10 取消操作

输入 `取消` 会清空客户端待确认候选项，并向服务端发送取消助手合成任务请求。普通 AI 聊天 HTTP 请求的取消按钮只取消当前聊天请求，不等同于取消 AE2 合成任务。

### 8.11 计划功能

示例：

```text
创建计划 明天检查铱生产线
列出计划
完成第 1 个计划
```

该计划功能是轻量级助手功能，不是复杂任务系统。

## 9. 语音助手

语音助手使用本地录音，把音频编码为 WAV 后发送到 OpenAI-compatible `/v1/audio/transcriptions` 接口。转写出的文字会提交到 AI 窗口，并复用同一助手流程。

需要设置：

```text
voice.enabled=true
```

STT API Key 来源优先级：

1. `voice.sttApiKey`
2. 环境变量 `VOICE_STT_API_KEY`
3. `ai.apiKey`
4. 环境变量 `DEEPSEEK_API_KEY`

STT 模式由 `voice.sttMode` 控制：

- `embedded-vosk`：默认离线模式。Windows 64-bit Java 下直接使用模组内置 Vosk 中文模型，不需要 Python、本地服务或 API Key。
- `http`：OpenAI-compatible `/v1/audio/transcriptions` 模式，适合接 Whisper 服务或云端 STT。

HTTP 模式下，STT Base URL 来源：`voice.sttBaseUrl`，为空则使用 `ai.apiBaseUrl`。HTTP 默认 STT 模型为 `whisper-1`。

默认语音推荐使用内置 Vosk 模式。它会把随模组携带的中文小模型解包到配置目录，不需要玩家安装 Python 或启动额外服务。

```text
voice {
    B:enabled=true
    B:privacyConfirmed=true
    S:sttMode=embedded-vosk
    S:sttBaseUrl=
    S:sttApiKey=
    S:sttModel=zh-small
    I:sttTimeoutSeconds=60
}
```

如果使用带 voice 的发布包，`zh-small` 模型会随模组自动解包到配置目录；如果使用普通包，也可以把 `voice.sttModel` 设置为本地 Vosk 模型目录。

如果要改用 HTTP/Whisper 模式，可以设置：

```text
voice {
    B:enabled=true
    B:privacyConfirmed=true
    S:sttMode=http
    S:sttBaseUrl=http://127.0.0.1:8000
    S:sttApiKey=
    S:sttModel=whisper-1
    I:sttTimeoutSeconds=120
}
```


使用流程：

1. 在 AI 设置界面或配置文件中启用语音助手。
2. 确认语音隐私提示。
3. 使用客户端注册的语音快捷键开始录音。
4. 停止录音后等待 STT 返回文字。
5. 如果当前没有打开 AI 界面，客户端会打开 AI 窗口并提交转写文本。
6. 后续流程与文本助手相同。

注意：语音会发送给配置的 STT 服务商，请勿朗读敏感信息。

## 11. 配置文件详解

### 11.1 配置文件位置

Forge 通常会生成：

```text
.minecraft/config/textech/textech.cfg
```

服务器则位于服务端实例的：

```text
config/textech/textech.cfg
```

具体路径为 `config/textech/textech.cfg`；客户端 AI 密钥另存 `config/textech/ai-client-local.cfg`。**整包分享 `.minecraft` 或 GTNH 整合包前，请删除或清空 `ai-client-local.cfg`**（或改用 `DEEPSEEK_API_KEY` 环境变量），避免密钥随包泄露。

### 11.2 `general` 分类

```text
general {
    S:greeting=Hello World
}
```

`greeting` 是启动日志中的问候文本，对游戏功能基本无影响。

### 11.3 `ai` 分类

```text
ai {
    S:apiBaseUrl=https://api.deepseek.com
    S:apiKey=
    S:model=deepseek-chat
    B:networkEnabled=true
    B:webSearchEnabled=false
    S:webSearchMode=auto
    S:searchApiKey=
    S:searchBaseUrl=
    I:searchMaxResults=5
    B:searchFallback=true
    B:debugLogging=false
    B:streamingEnabled=false
    B:privacyConfirmed=false
    S:recentModels=
    I:timeoutSeconds=60
    I:maxTokens=1024
    D:temperature=0.7
}
```

字段说明：

- `apiBaseUrl`：OpenAI-compatible Chat API 地址。默认 `https://api.deepseek.com`。
- `apiKey`：Chat API Key，也可用环境变量 `DEEPSEEK_API_KEY`。
- `model`：模型名，默认 `deepseek-chat`。
- `networkEnabled`：是否允许 AI 发送网络请求。关闭后普通 AI 和 AI intent 主路径不可用。
- `webSearchEnabled`：是否在调用 LLM 前启用内置联网搜索。
- `webSearchMode`：内置搜索引擎，可选 `auto`、`tavily_keyless`、`duckduckgo`、`tavily`、`brave`、`serper`、`searxng`。
- `searchApiKey`：Tavily / Brave / Serper 搜索引擎 API Key，也可用环境变量 `AI_SEARCH_API_KEY`。
- `searchBaseUrl`：自建 SearXNG 实例 URL（使用 `searxng` 引擎时必填）。
- `searchMaxResults`：注入 LLM 的搜索结果数量，范围 `1` 到 `10`，默认 `5`。
- `searchFallback`：某个搜索引擎失败时是否自动尝试链上下一个引擎。
- `debugLogging`：是否写入脱敏后的 AI 请求诊断日志。
- `streamingEnabled`：普通聊天是否使用流式响应。AI intent 解析会强制使用非流式。
- `privacyConfirmed`：是否已确认 AI 隐私提示。
- `recentModels`：最近使用模型列表，逗号分隔，最多保留 8 个。
- `timeoutSeconds`：HTTP 超时秒数，范围 `5` 到 `300`。
- `maxTokens`：模型最大返回 token，范围 `1` 到 `8192`。
- `temperature`：采样温度，范围 `0.0` 到 `2.0`。

### 11.4 `voice` 分类

```text
voice {
    B:enabled=false
    B:privacyConfirmed=false
    S:sttMode=embedded-vosk
    S:sttBaseUrl=
    S:sttApiKey=
    S:sttModel=zh-small
    I:sttTimeoutSeconds=60
}
```

字段说明：

- `enabled`：是否启用语音助手热键和 STT 流程。
- `privacyConfirmed`：是否已确认语音隐私提示。
- `sttMode`：语音识别模式，默认 `embedded-vosk`。可选 `embedded-vosk` 或 `http`。
- `sttBaseUrl`：OpenAI-compatible STT API 地址，仅 `http` 模式使用。为空时使用 `ai.apiBaseUrl`。
- `sttApiKey`：HTTP STT API Key。为空时依次尝试 `VOICE_STT_API_KEY`、`ai.apiKey`、`DEEPSEEK_API_KEY`；`embedded-vosk` 模式不需要。
- `sttModel`：语音转文字模型。`embedded-vosk` 默认 `zh-small`，也可填本地 Vosk 模型目录；`http` 常用 `whisper-1`。
- `sttTimeoutSeconds`：STT HTTP 超时秒数，范围 `5` 到 `300`。

### 11.5 `assistant` 分类

```text
assistant {
    I:maxOrderAmount=4096
    I:maxWithdrawAmount=4096
    I:craftJobTimeoutSeconds=30
    I:maxConcurrentCraftJobs=2
}
```

字段说明：

- `maxOrderAmount`：助手单行合成订单允许的最大数量，默认 `4096`，范围 `1` 到 `1000000`。
- `maxWithdrawAmount`：助手单次取出物品允许的最大数量，默认 `4096`，范围 `1` 到 `1000000`。
- `craftJobTimeoutSeconds`：AE2 合成计算等待超时秒数，默认 `30`，范围 `1` 到 `300`。
- `maxConcurrentCraftJobs`：每名玩家最多同时进行的助手 AE2 合成计算数量，默认 `2`，范围 `1` 到 `16`。

注意：`ConfigAssistantLoader.save()` 现已同步写入 `[assistant]` 节全部字段（含 `craftJobTimeoutSeconds`、`maxConcurrentCraftJobs`、`linkSearchRadius` 等）。游戏内 **AI 设置** GUI 仍只保存客户端 AI/语音偏好；服务端 `[assistant]` 数值项请直接编辑 cfg 或通过 `/admassistant` 等命令调整。

- `linkSearchRadius`：助手搜索附近 AE2 链接方块的半径（格），默认 `32`，范围 `4`–`128`。

## 13. 内置联网搜索

AI 助手采用 **统一检索 + 上下文注入** 方案：启用搜索后，客户端先用配置的搜索引擎检索网页，把结果格式化为文本拼入用户消息，再调用任意 LLM 生成回答。**不依赖** DeepSeek 等服务商自带的 search 参数，任意 OpenAI-compatible 模型均可联网。

### 13.1 搜索引擎

| ID | 说明 | 是否需要 Key |
|----|------|-------------|
| `auto` | 自动模式，按链依次尝试 | 视链上引擎而定 |
| `tavily_keyless` | Tavily 免 Key | 否 |
| `duckduckgo` | DuckDuckGo HTML 检索 | 否 |
| `tavily` | Tavily 正式 API | 是 |
| `brave` | Brave Search API | 是 |
| `serper` | Serper / Google 结果 | 是 |
| `searxng` | 自建 SearXNG 实例 | 需配置 URL |

`auto` 降级链：`tavily_keyless → duckduckgo → tavily → brave → serper → searxng`。未配置 Key 的付费引擎和未配置 URL 的 SearXNG 会自动跳过。

### 13.2 使用方式

1. AI 对话界面打开「搜索：开」，或使用「下次搜索」单次覆盖。
2. AI 设置 GUI（齿轮）配置搜索引擎、Search Key、SearXNG 地址、结果数、降级策略。
3. `/admai search on` 开启；`/admai search auto` 使用自动模式（开箱可用）。

搜索失败时聊天区会显示 warning，模型仍会继续回答。成功时会在回复前显示「引用来源」列表。

客户端 AI/搜索配置保存在 `config/textech/ai-client-local.cfg`，不会上传到专用服。

## 14. 常见使用场景

### 14.1 做一个 AE 存储占用趋势图

1. 将高级网络链接器接入 AE 网络。
2. 在监视器新增绑定，坐标填链接器方块。
3. 选择显示类型「网络统计图表」；数据名选择 `ItemUsedBytes`。
4. 显示方式选择百分比。
5. 图表类型选择折线图。
6. `interval` 设置为 `100`，约 5 秒刷新一次。
7. `dataLimit` 设置为 `200`，观察较长趋势。

### 14.2 做一个合成 CPU 总览屏

1. 将高级网络链接器接入 AE 网络。
2. 在监视器新增绑定，坐标填链接器方块。
3. 选择显示类型「合成监控」，进入合成处理器配置。
4. 监控范围选择“全网络”。
5. 调整文字缩放和位置，让文字悬浮在监视器前方。
6. 保存。

### 14.3 做一个关键材料库存墙

1. 给多个高级存储链接元件配置分区槽，例如铱锭、钨钢、锡锭、电路。
2. 把元件放入高级网络链接器方块（右键打开 GUI）。
3. 在监视器新增绑定，坐标填链接器方块；选择显示类型「存储显示」。
4. 设置 `storageColumns=4`、`storageSpacing=0.45`、`storageIconScale=1.0`。
5. 保存后监视器显示关键材料库存。

### 14.4 用挂索系统参观基地与产线

1. 在产线参观路径、景观连桥、多层竖井等位置放置**挂索节点**（Shift+右键可命名，便于识别）。
2. 手持**挂索器**走到起点附近，磁吸选中节点后右键挂接。
3. 转动视角选中下一个目标节点（图标变绿），右键开始滑行。
4. 沿途可自由观赏建筑与产线细节；需要停下时按 Shift 取消挂接。
5. 可在挂索器设置中调整滑行速度，或关闭节点名称/距离显示以获得更简洁的 HUD。

适合替代「直接传送到下一层」或「按住飞行键赶路」的场景——当你希望**看见路上**而不是一闪而过时使用。

### 14.5 用 AI 帮忙下单

1. 确保附近 32 格内有高级网络链接器。
2. 打开高级数据监视器的 AI 界面。
3. 输入 `帮我合成 64 个锡齿轮和 32 个铜线`。
4. 等待候选项列表。
5. 如果候选正确，输入 `确认`；如果候选不唯一，输入对应序号。

### 14.6 用 AI 取出 AE2 物品到背包

1. 确保附近 32 格内有高级网络链接器。
2. 打开高级数据监视器的 AI 界面。
3. 输入 `取出 64 个锡锭到背包`。
4. 等待候选项列表。
5. 如果候选正确，输入 `确认`；如果候选不唯一，输入对应序号。
6. 物品会自动转入玩家背包。如果背包空间不足，助手会提示可放入的数量，输入"确认"即可取出部分。

## 15. 常见问题排查

### 15.1 监视器没有显示

检查显示项是否启用、主界面是否隐藏了屏幕或本体、`scale` 是否太小、偏移是否不合适、目标坐标是否正确、目标方块是否为 TileEntity、`interval` 是否过大。

### 15.2 图表一直是 0

检查 `name` 字段是否正确；用数据映录器查看目标 TileEntity NBT；若绑定高级网络链接器且显示网络图表，确认数据名是否是 `ItemUsedBytes` 等支持字段；确认目标区块已加载。

### 15.3 高级网络链接器没有网络统计数据

检查方块是否接入 AE2 网络、网络是否有频道、网络中是否有 Drive 或 Chest 存储单元、Shift+右键方块是否能输出综合状态。

### 15.4 高级网络链接器看不到 CPU

检查方块是否接入和合成 CPU 同一个 AE2 网络、网络是否有频道、网络中是否存在合成 CPU、多方块结构是否有效、CPU 名称是否和模板中写的一致。

### 15.5 高级网络链接器不显示存储物品

检查高级网络链接器是否接入 AE2 网络、元件是否已经在 AE2 Cell Workbench 中配置分区物品、元件是否放入链接器 GUI（右键打开）、分区物品在 AE 网络中是否存在、是否安装了 Inverter Card、监视器绑定坐标是否正确且显示类型为「存储显示」。

### 15.6 AI 提示没有 API Key

使用 `/admai key sk-...` 设置，或编辑配置 `ai.apiKey`，或设置环境变量 `DEEPSEEK_API_KEY`，并确认 `ai.networkEnabled=true`。

### 15.7 AI 联网已关闭

使用 `/admai network on`，或在配置文件中设置 `B:networkEnabled=true`。

### 15.8 AI 能聊天但不能执行 AE2 操作

检查附近 32 格内是否有高级网络链接器方块。查询存储、样板与下单均通过该统一链接器进入 AE2 网络；方块必须接入 AE2 网络并有频道。

### 15.9 批量下单失败

常见原因：某一行没有匹配到候选项、数量超过 `assistant.maxOrderAmount`、可用 AE2 合成计算槽不足、玩家附近没有高级网络链接器、AE2 合成计算超时。

### 15.10 语音助手不可用

检查 `voice.enabled=true`、已确认语音隐私提示、麦克风可用。Windows 默认 `embedded-vosk` 无需 STT Key；若使用 `http` 模式，还需配置 STT Key 与支持 `/v1/audio/transcriptions` 的 Base URL。非 Windows 须设 `voice.sttMode=http`。

### 15.11 AI 取出物品功能不可用

检查附近 32 格内是否有高级网络链接器方块、方块是否接入 AE2 网络并有频道、AE2 网络中是否有可匹配的物品、是否使用了正确的关键词（"取出""拿""给我"等）。

### 15.12 取出物品提示数量是 0 或报错

检查 AE2 网络中的物品库存是否充足、背包是否已满、`assistant.maxWithdrawAmount` 是否太小、高级网络链接器是否正常工作。

### 15.13 提示绑定已满

每个监视器面最多 36 条绑定。删除不需要的显示项，或切换到其他面后再添加。这与单条图表的 `dataLimit`（默认 100 个数据点）无关。

## 16. 服务器管理员建议

- 不建议让大量监视器使用 `interval=1` 高频刷新。
- 对公共服务器，建议限制 `assistant.maxOrderAmount`，避免误下超大订单。
- 根据服务器性能调整 `assistant.maxConcurrentCraftJobs` 和 `assistant.craftJobTimeoutSeconds`。
- 如果启用 AI，建议明确告知玩家输入内容会发送到外部模型供应商。
- 不建议把真实 API Key 写入公开发布的整合包配置。
- 如果使用 AI debug logging，注意虽然代码会尽量写脱敏诊断，但仍应避免长期开启。
- 为本模组补配方时，建议让 AE2 链接器方块成本与其服务器价值相匹配。

## 17. 已知限制

- 部分物品仍无内置配方（挂索、编织元件、堆叠升级卡、战斗特殊物品等）；核心监视/链接器/映录器/口袋等已有 GT Assembler/装配线配方，见 §2.4。
- AE2 查询链接器搜索半径默认 32 格，可通过 cfg `assistant.linkSearchRadius` 配置（4–128）。
- AI intent 单次最多处理 8 个 task。
- AI 输出非法时会整体退回规则 parser，而不是跳过单个错误 task。
- 取出物品需要玩家背包有足够空间；空间不足时会触发部分取出确认流程。
- 批量取出时如果某一行需要部分确认，整个批量操作会暂停。
- 普通聊天历史只保存在客户端内存中，关闭游戏后不会持久化。
- 存储和合成查询结果多数是格式化文本，不是结构化 UI 数据。
- 批量订单合并主要按自然语言 target 字符串，不按物品注册名彻底规范化。
- 高级网络链接器网络统计主要遍历 AE Drive/Chest 中的存储单元，特殊存储结构可能不完全覆盖。
- 合成 CPU 显示受 AE2 API 限制，部分处理样板的非物品输入/输出可能无法完整展示。
- 语音助手默认 `voice.sttMode=embedded-vosk`（Windows 64-bit 离线）；非 Windows 须设 `voice.sttMode=http` 并配置外部 STT。

## 19. 高级计划器

> 开发者 API 详见 [开发者技术文档 §5.11](../developer/技术文档.md#511-advance-planner高级计划器)

### 19.1 物品简介

**高级计划器**（Advance Planner）是 TeXTech 模组提供的一个轻量级任务规划工具。你可以把它理解为一个"游戏内的待办清单"——在其中记录你需要完成的事项，逐条勾选，并支持将多个计划器的内容整合到一起。

**核心特性：**

- 每个计划器可存储**多条待办条目**
- 每条条目支持**文本描述**和**完成状态**
- 支持**滚动翻页**，最多可容纳 50 行显示
- 支持将背包中所有计划器**整合为一个**
- 支持在屏幕 HUD 上显示待办列表

---

### 19.2 获取方式

在创造模式下，高级计划器位于 **工具 (Tools)** 标签页中，搜索"计划器"或"Planner"即可找到。

| 中文名称 | 英文名称 | 内部 ID |
|---------|----------|---------|
| 高级计划器 | Advance Planner | `textech:advance_planner` |

---

### 19.3 基本操作

#### 19.3.1 打开计划器 GUI

**右键点击**（不潜行）手持的高级计划器，即可打开计划器界面。

#### 19.3.2 添加条目

1. 打开 GUI 后，你会看到一个列表区域，最多显示 8 行（可通过滚轮翻页查看更多）。
2. **点击一个空行**（显示"点击添加..."的行），会弹出文本输入框。
3. 输入你想要记录的内容，然后点击绿色的 **"添加"** 按钮确认，或按 **Enter** 键确认。
4. 如果不想添加，点击红色的 **"X"** 按钮取消，或按 **Esc** 键取消。

> **注意：** 如果输入框为空就确认，新条目不会被创建；编辑已有条目时若清空内容后确认，**将删除该条目**（与按 X 删除等效）。

#### 19.3.3 编辑条目

**点击已有条目的文本区域**，即可进入编辑模式。编辑完成后按 Enter 或点击"添加"按钮保存。

#### 19.3.4 勾选完成 / 取消完成

- 每行最左侧有一个 **复选框**。
- **点击复选框** 即可切换该条目的完成状态。
- 已完成的条目会显示为**绿色**并带有**删除线**效果。
- 未完成的条目显示为**白色**。

> 鼠标悬停在复选框上时，会显示提示文字"标记为已完成"或"标记为未完成"。

#### 19.3.5 滚轮翻页

当条目数量超过一屏（8 行）时，使用**鼠标滚轮**上下滚动列表。右侧会显示滚动条指示当前位置。

### 19.5 整合功能（合并多个计划器）

当你背包中有**多个**高级计划器时，可以将它们的内容合并到一个计划器中。

#### 19.51 操作步骤

1. 确保背包中有 **2 个或以上** 高级计划器。
2. 右键打开其中任意一个计划器。
3. 点击底部的 **"整合"** 按钮。
4. 进入整合确认界面，会显示：
   - 背包中计划器的数量和总条目数
   - 每个计划器的条目数量（当前打开的会标注"（当前）"）
5. 选择合并模式（见下文）。
6. 点击 **"确认整合"** 执行合并。

#### 19.52 合并模式

| 模式 | 说明 |
|------|------|
| **按时间合并** (Merge by Time) | 将所有条目按添加时间排序，时间早的排在前面 |
| **按序号合并** (Merge by Index) | 保持原计划器的条目顺序，先放第一个计划器的全部条目，再追加第二个的，依此类推 |

#### 19.53 合并规则

- 合并后，所有条目会重新编号（从 1 开始连续编号）。
- 每条条目的**文本内容**、**完成状态**和**原始时间戳**都会被保留。
- 合并操作会**消耗**其他计划器物品（从背包中移除），只保留当前这个。
- 合并完成后自动回到计划器主界面，可立即查看结果。

#### 19.54 取消整合

在整合确认界面点击 **"取消"** 按钮，将返回计划器主界面，不会执行任何合并操作。

### 19.8 使用技巧

1. **分类管理：** 准备多个计划器，分别用于不同目的（如"建造计划"、"材料清单"、"探索目标"），需要时再整合。

2. **利用完成状态：** 完成的条目带有删除线效果且颜色不同，方便快速区分进度。

3. **整合前检查：** 整合前可以在确认界面查看每个计划器的条目数，确认无误再操作。

4. **HUD 实用场景：** 在建造大型项目时，潜行+右键开启 HUD，就能在游戏画面上随时看到待办列表，无需反复打开 GUI。

5. **不可堆叠：** 每个高级计划器占用一个物品栏位（最大堆叠数为 1），请注意背包空间。

### 19.9 常见问题

**Q: 整合按钮灰色/不可用？**

A: 确保背包中至少有 2 个高级计划器。只有 1 个时无法整合。

**Q: 合并后原来的计划器去哪了？**

A: 合并会消耗掉其他计划器，只保留当前打开的那个。合并前请确认不需要保留原始物品。

**Q: 条目数量有上限吗？**

A: 显示区域最多同时展示 50 行（通过滚动翻页），实际存储的条目数量理论上没有硬性限制（受 NBT 数据大小约束）。

**Q: 编辑时按 Esc 会怎样？**

A: 按 Esc 会取消当前编辑，不会保存你正在输入的内容。

**Q: 关闭 GUI 时未保存的编辑会丢失吗？**

A: 不会。关闭 GUI 时，如果有正在编辑的条目，系统会自动提交当前编辑内容。
