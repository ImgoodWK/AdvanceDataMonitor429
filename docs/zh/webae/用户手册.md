## 1. 概述

WebAE 控制台（Web 控制台）是 TeXTech 提供的 **浏览器可访问** HTTP 管理面板。通过任意现代浏览器即可实时查看 AE2 存储、电力、GT 机器状态，搜索配方，编辑样板，提交合成订单，并与游戏内聊天互通。

| 功能 | 说明 |
|------|------|
| 仪表盘 | 141 套配色 × 36 种布局 × 138 种页面样式；主题工作室另有 28 个可搜索、收藏的一键设计包，并提供独立「顶级精选」入口；可拖拽自定义 widget 网格 |
| 存储 / 流体 / 源质 | 独立侧栏页；存储页亦含物品/流体/源质子表与总览 |
| 合成处理器 | 独立菜单查看 AE2 合成处理器状态与详情 |
| 电力监控 | 可配置布局：EU/蒸汽仪表、入出速率、双序列趋势图 |
| GT 机器 | 查看在线 GT 机器的运行状态、进度、当前配方 |
| 配方搜索 | 服务端上传后，在网页点「获取配方」同步到浏览器 IndexedDB，本地模糊搜索；支持合并/缩略/详细布局 |
| 样板管理 | 查看、新建、编辑、注入 AE2 样板到 ME 接口 |
| AE 下单 | 按样板/物品/材料树提交单笔合成订单，可选 CPU，真实 AE2 进度追踪 |
| 网络拓扑 | 逻辑/空间/P2P/**世界地图** 四视图；频道预算车道（致密 32→4×智能 8）与角色舱；CSV 导出 |
| 任务书 | BetterQuesting 任务线/路线图/提交协助（需安装 BQ） |
| 链接扫描器 | 浏览游戏内扫描结果、别名与传送 |
| 监视器绑定 | 只读查看绑定槽位；按类型预览数值/进度/折线/柱状/饼图/表格 |
| 计划器 | 同步查看/管理高级计划器条目 |
| AI 助手 | 网页端对话入口（复用游戏内助手能力） |
| 告警历史 | 查看自动化告警记录；规则见设置/告警编辑 |
| Spark 性能分析 | 需安装 Spark 模组；管理控制台内直接查看方法热点、影响分类和智能建议，并对比两次采样；Viewer 仅作为可选高级入口 |
| 服务端后台 | 管理员按需执行服务端命令、保存共享常用命令、按在线/离线/全部筛选并快捷插入玩家名称或 UUID；含二次确认和有界审计 |
| QQ 群机器人 | 管理员配置 QQ 开放平台官方机器人；群成员可查询人数/TPS/在线名单/内存/运行时间并进行 AI 对话，支持定时播报、手动公告与审计 |
| 聊天 | 网页端与游戏内聊天互通，查看在线玩家列表 |
| 命令上传 | OP 用 `/textech web recipes upload`、`/textech web icons upload` 触发配方/图标上传（无游戏内快捷键） |

默认访问地址：`http://127.0.0.1:8090`（端口可在配置中修改）。

## 2. 启用与配置

WebAE 是 TeXTech 2.0 的可选下载，不在主模组 JAR 内。请从同一版本的 GitHub Release 下载 `textech-*-webae.zip`，直接解压到**服务端实例根目录**；安装完成后应存在：

```text
TeXTech/WebAE/ui/index.html
```

不使用 WebAE 时无需下载该 ZIP。未安装网页资源时，WebAE 后端 API 仍可随配置启动，但浏览器访问 `/` 会显示资源未安装提示，不能使用控制台页面。升级时用新版本 ZIP 覆盖整个 `TeXTech/WebAE/ui/`，并保持 ZIP、主 JAR 版本一致。

Web 控制台默认 **关闭**。安装资源后，在 `config/textech/textech.cfg` 中修改 `[webConsole]` 节：

```ini
[webConsole]
enabled=true
port=8090
bindAddress=127.0.0.1
aiServerKeyEnabled=true
aiBrowserKeyEnabled=false
refreshIntervalMs=1000
gtRefreshIntervalMs=10000
maxNetworksDisplayed=5
tokenLifetimeHours=0
maxRecipeCacheMB=256
recipeCacheMode=full
recipeUploadBatchesPerTick=3
recipeSearchMinIntervalMs=1000
recipeKeepMemoryAfterUpload=false
recipeSyncChunkSize=400
nesqlRepositoryPath=
neiDeepScanItemsPerTick=0
iconMissingDispatchPerTick=8
iconDirectRenderEnabled=false
iconDirectRenderTimeoutMs=3000
iconDirectRenderPerTick=4
powerSampleWindowSeconds=60
gtDefaultScanRadius=16
recipeUploadEnabled=true
iconCacheEnabled=true
iconUploadEnabled=true
iconPackEnabled=true
sparkEnabled=true
sparkMaxHistory=50
sparkDefaultDurationSeconds=30
sparkMaxDurationSeconds=300
```

修改后 **重启服务端** 即可生效。常用项：

- `refreshIntervalMs`：服务端采集与前端轮询的统一刷新间隔（毫秒），默认 1000，最低 1000。
- `gtRefreshIntervalMs`：GT 机器采集间隔（毫秒），默认 10000。
- `maxNetworksDisplayed`：网页同时显示的网络数上限（1–20，默认 5）。
- `tokenLifetimeHours`：Token 有效期（小时），0 = 永不过期。
- `recipeCacheMode`：`full`（GTNH 默认，不 LRU 淘汰）或 `lru`（超过 `maxRecipeCacheMB` 时淘汰；仅服务端内存已加载时生效）。
- `recipeKeepMemoryAfterUpload`：上传写盘后是否保留服务端内存全量配方；默认 `false`（清堆，由浏览器「获取配方」分块同步）。
- `recipeSyncChunkSize`：浏览器同步每块配方条数（默认 400）。
- `nesqlRepositoryPath`：NESQL 仓库根路径，供 `/textech web icons import-nesql` 使用。**留空时默认** `<实例根>/TeXTech/WebAE/`（客户端为 `.minecraft/TeXTech/WebAE/`，专用服为服务端根目录下同名文件夹；与配方本地导出目录相同）。
- `bindAddress=127.0.0.1` 仅本机访问；改 `0.0.0.0` 开放局域网（请配合防火墙）。
- `aiServerKeyEnabled`：是否允许使用管理员维护的服务端共享 AI 配置（默认 true；从旧 `aiKeyMode=browser` 迁移时为 false）。
- `aiBrowserKeyEnabled`：是否允许每个浏览器保存个人 AI 配置并直连 Provider（默认 false；从旧 `aiKeyMode=browser` 迁移时为 true）。两者可同时开启；都开时在 Settings →「AI 与 API」选择优先来源（存于本浏览器）。
- `aiKeyMode`：已弃用的互斥模式，仅作迁移种子，请改用上面两个开关。
- `sparkEnabled` 默认开启，但仅在安装 Spark（Forge 1.7.10）时生效；没有 Spark 时管理控制台的 Spark 标签和接口会自动隐藏/返回不可用。
- `sparkMaxHistory` 控制服务端保留的运行记录数量；记录写入 `TeXTech/WebAE/spark-history.json`，包含状态、发起者、有限大小的本地热点/分类/线程摘要、上下文输出和可选 Spark Viewer URL。
- `sparkDefaultDurationSeconds` 与 `sparkMaxDurationSeconds` 控制管理控制台中的采样时长。WebAE 会在设定时长到达时显式停止 Spark；Viewer 上传可能额外等待，但不会延长采样。启动、停止、恢复 Viewer 链接和删除历史需要 WebAE 管理员权限。
- 「管理控制台 → Spark 性能分析」提供三种按需模式：**服务主线程**（默认、低开销）、**慢 Tick 聚焦**（只保留超过阈值的 tick）、**全部线程**（信息最广、开销较高且间隔最低 10ms）。可调整采样间隔和慢 tick 阈值；建议优先使用默认模式，全部线程只做短时诊断。
- 采样停止后，WebAE 从 Spark 已停止的本地调用树生成方法自身耗时热点、影响分类和线程占比；「智能性能诊断」默认按独占采样占比给出带具体类/方法证据的确定性本地建议，不需要先打开 Viewer。管理员可显式点击「使用 AI 深度分析」或在双记录对比中点击「使用 AI 分析对比」；这时只发送有界聚合摘要，绝不发送 API Key、Viewer 链接或原始输出，变化固定按 `B − A`。详情页同时保留开始/结束两次 Spark TPS/MSPT/CPU 上下文；完整 Viewer 仅放在折叠的高级区域。
- 勾选两条记录后，WebAE 按类别和方法展示 `B − A` 占比变化：正数表示影响变大，负数表示改善。应优先对比模式、间隔和复现场景一致的采样；旧版记录没有本地分析数据，只能比较基础元数据。
- 空闲时该标签不会增加 tick 采集、世界扫描或后台 Spark 日志轮询；只有采样运行中网页每 3 秒刷新内存状态，停止后短时间等待上传。完整交互式火焰图仍可按需打开 Spark Viewer。

完整配置项说明见 [开发者手册 §4](开发者手册.md#4-配置)。

## 3. 获取访问令牌

**命令索引**：游戏内执行 `/textech help`（别名 `/adm`、`/txt`）可查看全部域入口（`ai` / `assistant` / `web`）。Web 域主推 `/textech web …`；旧根命令 `/admweb`（及 `/adm-web`、`/webconsole`）仍可用。

Web 控制台需要 Token 认证。在游戏中（或服务端控制台）使用命令：

| 命令 | 说明 |
|------|------|
| `/textech web issue` | 生成**主人** Token（须至少拥有 1 块高级数据监视器；完整值仅显示一次） |
| `/textech web login` | 生成 **6 位浏览器登录码**（5 分钟有效、单次使用；无需 OP 签发 Token） |
| `/textech web guest <玩家名>` | 监视器主人向**在线**访客私发**只读访客** Token（仅访问主人允许的 AE 网络；聊天显示访客名） |
| `/textech web copy` | 将当前活跃 Token 复制到剪贴板 |
| `/textech web list` | 列出 Token 类型、owner、actor（仅 OP） |
| `/textech web revoke [访客名]` | 撤销自己的主人 Token；主人可撤销指定访客 Token；OP 可撤销他人 |
| `/textech web reload` | 重载 TeXTech 配置；`enabled`/`port`/`bindAddress` 等仍需重启服务端（仅 OP） |
| `/textech web refresh [网络]` | 管理员强制重采集快照（仅 OP） |
| `/textech web server status` | 查看 WebAE HTTP 服务运行状态 |
| `/textech web server restart` | 重启 HTTP 服务（仅 OP） |
| `/textech web recipes upload [snapshot\|deep]` / `export` | **OP** 触发自己客户端采集上传 NEI 配方到服务端磁盘；同时写入客户端 `<实例根>/TeXTech/WebAE/web-recipes.json`；网页还需点「获取配方」；`snapshot` 仅采集存储相关物品配方（日常推荐）；`deep` 全量 NEI 物品扫描（耗时） |
| `/textech web recipes status` | 查看配方缓存状态（含磁盘缓存大小） |
| `/textech web recipes clear` | 清空配方内存+磁盘缓存（仅 OP） |
| `/textech web icons upload [pack]` / `upload snapshot [pack]` | **OP** 触发客户端渲染并上传到服务端 |
| `/textech web icons local [pack]` / `local snapshot [pack]` | 任意在线玩家：渲到本机 `TeXTech/WebAE/icons-local/`（不上传） |
| `/textech web icons pull [pack]` | 任意在线玩家：把服务端已有 PNG 拉到本机 `icons-local/` |
| `/textech web icons y` / `n` | 懒加载补渲同意/拒绝（仅当 `iconLazyCaptureEnabled=true`） |
| `/textech web icons render <itemId> [pack]` | **OP** 渲染并上传单个物品图标 |
| `/textech web icons verify <itemId> [pack]` | 打开图标验证 GUI |
| `/textech web icons import <folder> [pack]` | **OP** 从本地文件夹导入 PNG |
| `/textech web icons import-nesql [pack] [subpath]` | **OP** 从 `nesqlRepositoryPath`（默认 `TeXTech/WebAE/`）导入预渲染 PNG（增量，不覆盖已有） |
| `/textech web icons modes` | 列出当前图标渲染 mode（仅 nei） |
| `/textech web icons status` | 查看已安装图标材质包与配置状态 |
| `/textech web icons clear` | 清空全部图标材质包（仅 OP；异步，不阻塞游戏，完成后聊天提示） |
| `/textech web worldmap upload [networkId]` | 上传世界地图快照（须在 AE 网络附近；客户端采集） |
| `/textech web worldmap accept <requestId>` | 同意访客/网页发起的地图上传请求（兼容旧用法） |
| `/textech web wm y [id]` | **推荐** 同意地图上传；可省略 id；聊天中点击「接受」等效 |
| `/textech web wm n [id]` | 拒绝地图上传请求 |
| `/textech web wm up [networkId]` | 等同 `worldmap upload` |
| `/textech web wm st [networkId]` | 等同 `worldmap status` |
| `/textech web worldmap status [networkId]` | 查看地图快照采集状态 |
| `/textech web help` | 显示用法（含 recipes/icons/worldmap/server 分组 help） |

**Token 类型**

- **主人 Token**：绑定监视器主人 UUID，可读写其名下全部监视器所连 AE 网络；**不要求主人在线**。
- **访客 Token**：由主人 `/textech web guest`（旧入口 `/admweb guest`）签发，只能读取主人 allowlist 内的 AE 网络；不能刷新、上传、下单、写样板或执行其他写操作。网页/游戏内聊天仍显示访客名。
- Token 数据写入 `TeXTech/WebAE/web-tokens.json`；旧格式条目首次加载时自动迁移为 `type: owner`。

**离线访问与区块**

- 仅**已加载区块**内的高级数据监视器会被发现；跨维度监视器的 `monitorDim` 已按监视器所在维度采集。
- 基地需常加载或使用区块加载器，否则网页网络列表可能为空。

## 4. 浏览器访问

1. 确认服务端已启动且 `enabled=true`
2. 打开浏览器，访问 `http://127.0.0.1:8090`（或服管配置的地址与端口）
3. 在登录页输入 `/textech web issue` 获取的 Token
4. Token 存储在浏览器 `localStorage` 中；**自动登录**（默认开启）会在下次访问时自动重连
5. 若 Token 过期或被撤销，登录页会提示并清除本地 Token，请重新签发
6. 需要更换 Token 时，在设置页输入新 Token 即可立即重连
7. 可在设置页关闭「自动登录」

## 5. 功能页面

### 存储监控

页面分为独立的「存储容量概览」和「库存明细」工作区，二者有明确标题、说明和留白。概览为可配置 GridStack widget（默认物品种类/流体种类/字节占用率等）；普通模式只显示设置与编辑入口，进入编辑态后才展开撤销/重做、添加、自动排列和重置工具；启用「浏览模式」后这些编辑入口全部隐藏。下方明细含物品/流体/源质子表，支持排序、搜索以及多网络「分开」/「合并」聚合。独立流体页另将总量概览、钉选趋势和库存表分区展示。

### 合成处理器

独立侧边栏菜单，分为可配置的「处理器健康概览」与「处理器及合成队列」两个工作区。点击表格行打开详情 Drawer（坐标、网络、存储、当前任务、预计剩余）；多网络 split 模式用 Tabs 切换。抽屉内可查看 network-wide 繁忙率趋势、历史任务表和容量摘要，并按 queued/running/completed/failed/cancelled/stuck/unknown 筛选。容量窗口可选 1 小时、6 小时、24 小时、7 天或 14 天，摘要显示并发峰值、P50/P95 耗时、排队时间、存储压力与只读 CPU 数估算。

主仪表盘下方也有当前首选网络的「CPU 历史与容量规划」区域：显示网络级繁忙率趋势、近期任务、状态筛选、容量窗口、瓶颈和建议。页面处于活动状态时最多每 30 秒刷新一次；切换网络会读取新网络。Dashboard 与 CPU 详情抽屉都会明确显示 unknown 和 truncated，不会用绿色成功状态掩盖不确定数据。

历史最多保留 14 天；服务端单次最多返回 500 条任务和 1000 个 CPU 快照，「结果已截断」表示请求或响应达到上限。unknown 使用警告标记，表示生命周期无法核实，不会被当作空闲或已完成。首次打开一个尚未激活的网络时，请求只会启用后续正常服务端采样，短暂空数据不代表网络空闲；服务重启时未完成任务也会保守显示为 unknown。历史和容量是只读规划信息，不会自动创建、拆分、改造 CPU，也不会自动修改或重下单。

### 电力监控

独立「电力运行概览」工作区承载全页 GridStack widget（默认 EU 仪表、入/出速率、蒸汽进度条、EU+蒸汽双序列趋势图等）。点「编辑布局」后展开完整编辑工具；浏览模式下编辑与设置按钮隐藏。SNL 0.2.5 只提供蒸汽存量而不提供真实容量，因此页面不会伪造“已存/上限”或 0%；给组件设置明确目标值后才会按目标显示进度。多网络模式使用醒目的网络切换条；切换后快照与历史趋势都会使用当前网络上下文，自动刷新时趋势图保持挂载且不闪烁。

### GT 机器

列表显示在线 GT 机器的名称、工作进度、配方、输入/输出仓物品。支持筛选、文本搜索与排序。

### 配方搜索

配方不常驻服务端内存供浏览器直查。流程：**OP 游戏内上传 → 服务端落盘 → 玩家在配方页点「获取配方」→ 分块写入本浏览器 IndexedDB → 本地浏览/搜索**。

- 进入配方页后点工具栏 **「获取配方」**（有服务端新 revision 时才需要；进度条可取消）。完成后即可模糊搜索、类别多选、完整/合并与缩略/详细布局；数据保存在本浏览器，不会自动重复下载。
- OP 需先执行 `/textech web recipes upload snapshot`（推荐）或 `upload`（全量）；采集同时写入客户端 `.minecraft/TeXTech/WebAE/web-recipes.json`（纯 JSON 备份）。
- 换浏览器/清站点数据后需重新「获取配方」。服务端 `/textech web recipes clear` 只清服务端，不影响已下载的 IndexedDB。

### 物品图标与材质包

物品表与配方输入/输出可显示真实游戏图标，失败时回退为缩写。图标加载采用：**本机目录 → IndexedDB → 服务端磁盘 → 缩写**（懒加载补渲默认关闭）。

- **本机目录**：设置页「选择本机图标目录」指向游戏 `TeXTech/WebAE/icons-local/`（需 Chrome/Edge 且页面为 https 或 localhost；局域网 http://IP 请用 ZIP 导入）。任意玩家可执行 `/textech web icons local` 渲到本机，或 `/textech web icons pull` 从服务端下载。
- **本地优先**：目录/IndexedDB 命中时不打服务端；OP `/textech web icons upload` 或导入写到服务端磁盘后按需请求即可。
- **自动同步（默认关闭）**：设置页「自动同步服务端材质包」开启后，登录时若版本变化会整包下载到 IndexedDB。
- **手动获取**：设置页「同步整包」；「补当前可见缺失」仅请求已有 PNG（不会默认触发游戏内渲染）。
- **服务端缓存**：OP `/textech web icons upload` / `import-nesql`；渲染固定 **`nei`**（NESQL 同款 64×64 FBO）。若磁盘 PNG 出现方形/异形缺块，用新版本模组重跑 upload 覆盖；网页偶发错图时可 **Ctrl+F5** 硬刷新，或清 IndexedDB / 重新选择本机图标目录。
- **GT++（miscutils）缺锭/板/棒图**：旧版全量 upload 会跳过 `getIconIndex==null` 的材质物品（尘有图、锭无图）。磁盘上的 `itemDustMix*` 是「Mix」特殊尘，**不是**锭的错名。请用当前版本重跑 `/textech web icons upload snapshot`（优先）或全量 `upload`；补完后网页 Ctrl+F5。
- **本机目录**：设置页可选 `icons` / `icons-local`；刷新后若浏览器收回权限，点一下页面或「刷新索引」重新授权。
- **同系列 meta 整批变缩写**：前端曾把 `gregtech:gt.metaitem.01:xxxx` 失败误标到裸 `gt.metaitem.01`，导致同物品其它 meta 也不请求。当前版本已改为仅 `:0` 等价标记；硬刷新后应恢复已有 PNG。
- **异步补图（默认关）**：`iconLazyCaptureEnabled` 默认 **false**。开启后缺图才入队，并向候选玩家发聊天同意（说明将使用其材质包外观）。同步直渲仍默认 **false**。
- **多人服建议**：OP 先 `/textech web icons upload snapshot`；玩家用 `icons local` / 选目录 / ZIP。

### 样板管理

样板页现在是接近游戏内样板终端的三栏工作台：左侧在「配方库 / 网络样板」之间切换，中间编辑当前样板，右侧管理 ME 接口、接口槽位和网页缓存区。

- **从配方创建**：配方库可按产物、材料、配方类型搜索，并按具体 handler 筛选；每条具体配方都可一键填入当前样板。合成样板使用 3×3 槽位，处理样板使用 9×3，带形状配方的空位不会被压缩。物品 meta/NBT 和流体输入会随配方保留。
- **编辑已有样板**：在网络样板列表或接口槽位点击已有样板即可载入，修改后「保存样板」会原槽回写，不再消耗新的空白样板。只有把新样板写入空接口槽时才从所选 AE 网络扣除 1 个空白样板。
- **接口工作区**：右栏同时显示完整方块 ME 接口和线缆接口部件、机器配方类型、启用槽位和已放置样板。可点击编辑，也可拖放到空槽；放到占用槽时确认后交换两个样板。
- **跨接口移动**：把样板移入网页专用缓存区，再选择另一个接口空槽放出；缓存按 owner 与 AE 网络隔离，最多 54 个物理样板，持久化在服务端 `TeXTech/WebAE/web-pattern-buffer.json`。它不是样板副本，移入后原接口槽会清空。
- **可编程仓室兼容**：安装社区模组 Programmable Hatches 后，编辑器会显示兼容开关。配方中的模具、透镜、催化剂等 `stackSize=0` 未消耗输入会标记为 `∞`，开启兼容后编码为 `programmablehatches:prog_circuit` 包装项；也可选中输入手动切换是否消耗。未安装模组时开关不可用。

写入新样板、移动、交换、缓存、删除和回写属于管理操作，需要 WebAE 管理权限。操作完成后页面会刷新接口和网络样板；若刚进入时列表仍在后台预采集，可稍候片刻或点「刷新」。

### 合成下单

顶部可选合成处理器或留空自动分配。「按样板」Tab 分页浏览 Grid + Interface 双源样板，支持虚拟滚动与单笔下单。「按物品」Tab 支持存储搜索与单笔下单。「材料树」Tab 输入 registry 名与数量，递归展开配方链并显示库存缺口（仅查看，不批量下单）。进行中/历史订单每 3 秒刷新；进度来自 AE2 `ICraftingLink` 与 CPU 的合成树步骤计数（与游戏内 CPU GUI 同口径，**不是**最终产物个数）。游戏内取消的任务会进入历史并标注取消。历史订单可点「再次下单」，确认后按原物品与数量重新提交。

### 网络拓扑

侧栏「网络拓扑」提供逻辑分组、空间分区、**P2P 频道** 与 **世界地图** 四种视图。逻辑视图是 **频道预算规划图**（`ae_budget_v2`）：控制器 → 致密干 32 → 四路智能车道（各 8）→ 角色舱（终端/总线/接口等）→ 设备；存储/CPU 等零频道设备挂在控制器环上。这不是真实 AE 布线。也可切换双环摘要。原「线缆模拟」视图已弃用（`topologySimulatedEnabled`，默认关闭）。P2P 视图按 frequency 列出隧道端点；支持 CSV 导出。

#### 世界地图视图

默认采用 **客户端快照**（`worldMapSnapshotMode=client_only`）：地图由在线玩家客户端采集并上传，服务端不渲染。

1. **首次使用**：先采集逻辑拓扑快照，再在网页点击 **「更新地图快照」**，或由网络主人在 AE 网络附近执行 `/textech web wm up`（或 `/textech web worldmap upload`）。
2. **JourneyMap**：整合包已装 JourneyMap 时，优先读取本地最高清 day 瓦片（`worldMapJourneyMapEnabled`，支持 JM 5.x 的 `{x},{z}.png` 命名）；无 JM 时使用低清 GL 快速渲染。**分辨率**：JM 源图约 1 像素/方块（512 px 区域瓦片）；Web 显示清晰度可在控制台选 quality 档位，或在 `textech.cfg` 调整 `webWorldMapDefaultQualityTier` / `webWorldMapMaxQualityTier`（最高 ultra=512 px/chunk）。
3. **访客请求更新**：网页点击「更新地图快照」后，附近玩家会收到带 **接受/拒绝** 可点击文字的聊天提示；也可执行 `/textech web wm y`（可省略 requestId）同意上传。同一请求不会重复刷屏。
4. **设备清单**：地图右上角「设备清单」按钮打开弹窗，不影响地图尺寸。
5. **设备图标与弹窗**：点击单个设备图标或聚类数字，打开**设备缩略列表**（仅含可查看详情的设备类型：接口、驱动器、CPU、总线、箱子、安全终端、等级维持器、控制器、IO 端口、量子桥、能源元件、P2P 等；终端/监视器/发射器/样板供应器不显示）。列表中点击一行打开右侧**详情抽屉**；聚类打开时地图会临时放大 1.5×，关闭弹窗后还原。平移/缩放地图不会自动关闭弹窗；弹窗内滚轮仅滚动列表。**悬停聚类数字**时显示各设备类型图标及数量（xN）。**合成处理器与 ME 控制器**为多方块结构，在聚类计数中各计为 **1 个设备**（详情抽屉仍列出各方块坐标）。
6. **左侧 AE 图例窗**：地图左侧常驻窄色条；鼠标移入展开，可勾选类别可见性、点击色块改色（同时影响 AE 透视层与设备图标描边）；**取消勾选后图例项仍保留**（变暗显示），仅隐藏地图上对应设备图标；锁定后只读（仍可移出收起）；各类别色块上的图标与地图设备图标同源（取该类别首个设备），「其他」仅显示配置色块。原工具栏「AE 着色」按钮已移除。
7. **本地缓存**：浏览器会缓存已下载瓦片（IndexedDB）；换设备登录 MC 后客户端也会同步快照到 `TeXTech/WebAE/map-cache/`。
8. **AE 透视层**：与地形同时采集；**透明度**滑条（拓扑设置）仅影响 AE 设备着色像素（不影响地形）。
9. **滚轮**：在世界地图与树形拓扑视图中滚轮用于缩放，不会滚动整页。
10. **版本比较**：版本区默认选择 `previous → current`；也可分别选择起止版本或点击「比较上一版本」。地形始终保持 current，只在其上覆盖绿色新增、红色移除、蓝色移动与橙色变更；可单独开关 marker/tile。计数来自完整服务端 summary；详情被截断时会明确提示，unknown/partial 不会显示成“无变化”。
11. **服务端注释**：右键地图空白处或设备 marker 可新建注释；空白处 Y 默认 64。编辑器可设置标题、备注、颜色、维度/XYZ 和生效版本闭区间；边界 `0` 表示不限。点击图钉可查看、编辑或确认删除。正式注释保存在服务器，换浏览器仍可见，不使用浏览器 localStorage。
12. **只读权限**：guest token 和「浏览模式」仍可查看版本、差异与注释，但不会显示新建、编辑或删除入口；普通 owner 的写入仍经过当前网络 ACL。
13. **配置**：`worldMapSnapshotMode`、`worldMapJourneyMapEnabled`、`worldMapConsentRadiusChunks`、`worldMapOwnerSkipConsent` 等，详见 [开发者手册 §11.26](开发者手册.md#1126-世界地图视图三源采集--客户端快照--sp-直读)。

可靠性与清理：大型采集任务会分页传输并在客户端完整重组，不会拿截断的 chunk 清单开始上传；同一服务器最多保留 32 个 active jobs，90 分钟无活动或 2 小时后过期。采集玩家断线、WebAE 停止/重启或任务下发失败时，未发布快照会清理；网络主人免同意直采也遵守请求冷却。JourneyMap 只读取当前精确世界目录，路径中的 symlink、越界路径、超限或损坏 PNG 会被拒绝。

地图授权与文件边界：HD/客户端上传要求资源主人、OP，或当前 AE network active capture job 授权的真实玩家；owner UUID 必须是 canonical lowercase。manifest/current/tile 会校验大小、结构、坐标、layer 与 sha256，layer 仅允许 `terrain`/`ae`，quality 仅允许精确小写 `low|medium|high|ultra`。集成服 direct capture 仅在 integrated single-player 可用，并绑定待处理的 provider/request；Dynmap 代理的世界名、zoom、坐标、视角和文件路径也会限制在允许范围内。Dynmap 独立公开代理不等于 WebAE owner network 权限。

### 网络健康诊断

「性能诊断」页会为你有权查看的每个网络显示网络健康区块。它沿用网络选择器的 owner/网络权限，展示 runtime network id 与稳定监视器键（`dim:x:y:z`）、最近一次服务端检查、样本新鲜度，以及 Link 注册/可达、监视器绑定、AE Grid 存储/合成/连接器和频道使用量证据。问题行会附带简短说明与建议的下一步检查。

状态采用保守语义：**healthy** 表示必要证据完整，**degraded** 表示有 warning，**failed** 表示已确认的必要组件不可用，**unknown** 表示样本过期或证据无法验证；unknown 不会显示成绿色健康。采样在服务端 tick 中执行（约每 5 秒一次）；网页打开或刷新只读取缓存，不会在 HTTP 请求线程扫描世界。该功能只报告问题，不会自动修复绑定、重建 Grid 或修改频道配置。只读 API 为 `GET /api/network/health?network=<id>`，需要正常 WebAE 登录和网络 ACL。

### 任务书（BetterQuesting）

需整合包安装 **BetterQuesting**；侧栏「任务书」（`?page=quests`）为 **左侧任务线 | 中间路线图 | 右侧固定详情侧栏** 三栏布局（窄屏 ≤768px 时详情仍用抽屉）；工具栏「任务列表」按钮打开抽屉（含搜索与筛选）。左侧任务线旁显示 **已完成/总数**（如 `12/42`；全部完成时用成功色提示）。

- **图节点**：显示任务物品图标；主线任务（`isMain`）为菱形框，普通为圆角矩形；悬停高亮前后置节点与连线，并弹出任务名称提示（不依赖「显示任务名称」常驻标签开关）；可开关「隐藏已完成」；跨章节前置显示为虚线「外章」幽灵节点。工具栏提供 **放大 / 缩小 / 适应窗口** 与 **设置**（可调节节点间距、节点大小、标签、侧栏与连线等，保存在浏览器 localStorage）；**滚轮**在路线图区域以指针位置缩放（不滚动整页）；拖拽可平移视图。路线图节点名称可单独开关；标签显示去码文本并按首个 `§` 颜色着色。
- **§ 格式码**：任务标题、描述、步骤名等支持 Minecraft `§` 颜色与格式（如 `§a§l`）；详情侧栏与列表完整渲染样式，搜索匹配时会忽略格式码。
- **任务详情**：点击节点在**右侧固定侧栏**展示（无需额外打开抽屉）；区块顺序为关联任务（**前置** / **后续**）、提交条件（来自 BetterQuesting `tasks`）、奖励（来自 `rewards`；`bq_standard:choice` 显示多选一；纯物品奖励可网页领取）。点击前置/后续可跨任务线跳转并居中节点；隐式/隐藏前置显示对应标签。侧栏宽度可在设置中调节（默认 380px）。
- **刷新**：进入页面/切换章节时拉取一次进度与图数据并本地缓存；**无自动轮询**。手动刷新有 **30 秒冷却**；提交/领取相关操作前会强制刷新进度。
- **奖励领取**：当任务为 `UNCLAIMED` 且全部奖励均为可解析的纯物品（`bq_standard:item`）与多选一（`bq_standard:choice`）时，可在详情侧栏先完成选择，再确认「领取至 AE 网络」；物品经 BQ 官方领取后转入当前选中网络。AE 空间不足时拒绝领取并保持未领取。含命令/经验等非物品奖励时仍提示回游戏内领取。访客 Token 不可领取。
- **只读**：访客 Token 可浏览任务线与进度；不可提交、不可领取奖励。
- **Web 可协助**：物品/流体提交、Retrieval/流体持有检测（按 AE 库存完成，**不**把物品/流体装进玩家背包）；合成/击杀/维度类步骤仅展示。**流体单元任务**：DETECT 将游离流体与装满单元（默认 GT/IC2）加总；SUBMIT 优先扣装满单元，不足则用空单元+流体装填（禁止仅有流体）。真流体任务可从单元 drain 所需 mB（余量退回）。提交与「合成后提交」会用 **AE 虚拟 escrow** 锁定物料（合成开始前锁定已有，产物到账后立刻补锁），再提交或完成持有检测，失败/超时退回网络。可点击单个步骤提交；「链式提交」按拓扑顺序处理前置（可配置）。提交面板显示 AE 库存与需求对照；「可合成」仅在已有 AE 样板且材料链可满足时出现。若 `questFluidAllContainersOption=true`，面板可勾选「计入桶/罐等全部流体容器」。
- **离线**：主人不在线时仍可用 Token + FakePlayer 操作（进度写入 **Token 主人** 的 questing UUID）；需服务端运行且对应 AE 网络可解析（Link/区块加载），与其他 WebAE AE 操作前提相同。
- **组队**：Web 提交**不会**同步完成队友进度，只更新 Token owner；BQ 对 FakePlayer 强制单人，本模组未接 PartyManager / SyncPartyQuests。
- **配置**：`textech.cfg` → `[webConsole]` 的 `questEnabled`、`questSubmitEnabled`、`questClaimEnabled`（默认 true）、`questChainSubmitEnabled`（默认 true）、`questSubmitMaxStacks`、`questCraftWaitTimeoutMs`、`questEscrowEnabled`（默认 true）、`questEscrowTimeoutMs`（默认 120000）、`questFluidAllContainersOption`（默认 false）、`questCacheTtlSec`。

### 监视器绑定与预览

侧栏「监视器绑定」只读展示各数据监视器的槽位、来源与 GT 绑定坐标。点击槽位「预览」会按组件类型展示数值/进度、折线序列、柱状/饼图分类或表格行；预览固定在最多 240 个可视点内（只读，编辑仍在游戏内）。

### 链接扫描器 / 计划器 / AI 助手

- **链接扫描器**：展示游戏内高级链接扫描器的扫描结果，可按所有者/名称过滤并查看坐标（传送仍以游戏内为准）。
- **计划器**：同步高级计划器条目，便于在网页浏览与勾选进度。
- **AI 助手**：网页端与游戏内共用意图类型，支持自然语言查询存储/配方/电力/网络/计划，并可发起合成、取出与传送。启用服务器共享时使用管理员配置的多条有序 AI profile（失败按供应侧错误自动切换）；启用个人模式时当前浏览器直连 Provider，只把 AI 计划/回答交给 WebAE。两者都开时按浏览器偏好选择。联网搜索使用管理员共享的多引擎配置（个人模式由服务端代搜注入）。AI 未配置或解析失败时自动使用本地词库。合成、取出、传送必须在网页候选列表中再次确认；访客只能查询。AE 操作仍依赖附近高级网络链接器。

### 自动化告警与告警历史

`TeXTech/WebAE/web-alerts.json` 驱动库存阈值、CPU 卡住、GT 异常、下单完成、频道超载、低 TPS 与自动补货事件。`config/textech/textech.cfg` 的 `[webConsole] alertsEnabled=true` 是总闸（默认开启）；JSON 内的 `enabled` 和每条提醒渠道还能分别关闭。

设置 → 自动化告警可组合以下提醒方式，并按事件、级别及可选 owner UUID 过滤：

- 现有 WebAE Toast / 浏览器系统通知（轮询 + SSE 实时推送）；
- 告警所属在线玩家的聊天框与客户端 HUD（HUD 可设位置、时长、同时显示数和提示音）；
- 旧版 Discord/通用 JSON Webhook；
- QQ 开放平台官方机器人（群 `group_openid`、单聊用户 `openid` 或频道 ID）。设置页提供「获取目标 ID」：服务端主动连 QQ WebSocket 网关监听事件（无需公网回调），私聊/@ 机器人后可一键填入；开放平台需允许 WebSocket 与对应事件权限；
- 微信公众号客服文本或模板消息；
- SMTP 邮件（none / STARTTLS / SSL，支持 To/Cc）；
- 企业微信群机器人 Webhook，或企业微信自建应用消息。

初次使用时，点告警设置说明旁的 `?` 小按钮可查看“去哪里配置、要复制什么、填到哪里”的平台指南和官方入口。管理员可直接点「一键启用内置提醒」，一次保存 WebAE/浏览器、所属玩家聊天框与 HUD，并由这次点击申请浏览器系统通知权限；若浏览器拒绝，页面内 Toast 仍可用。外部平台用「立即配置」添加推荐默认目标，先填卡片上的必要字段；事件/级别/owner 过滤、API/Token 地址覆盖、SMTP 抄送与主题等特殊需求在该目标的「高级」中修改。

浏览器、玩家聊天默认开启；HUD 默认只显示 warning/error；外部目标默认列表为空，不会在升级后自动向第三方发送。外部密钥与完整 Webhook URL 仅写在服务端文件，网页/API 只显示掩码。QQ 主动消息仍受机器人权限和平台频率限制；公众号客服消息通常要求用户在平台规定的互动时间窗内，模板模式需账号模板权限且模板包含 `first`、`keyword1`–`keyword4`、`remark` 字段。侧栏「告警历史」可回看已触发记录；玩家离线不会触发全服扫描，告警仍保留在 Web 历史中。

所有 DNS、TLS、OAuth、SMTP、重试都在固定容量后台队列执行。外部目标或 Discord/通用 Webhook 填完后须先保存，才可点「发送测试」；成功提示表示测试已入队，不代表第三方最终送达。设置页会显示队列深度、送达/失败/丢弃和熔断目标数，应结合实际收件结果判断；第三方不可用不会阻塞服务器 Tick。

### 服务端后台

WebAE 管理员可在「管理控制台 → 服务端后台」执行 Minecraft 服务端命令。开头的 `/` 可省略；命令以服务端控制台最高权限在主线程执行，因此停服、封禁、OP/白名单等高风险命令会强制二次确认。页面一次只提交一条命令，服务端还会限制单并发、短冷却和主线程队列深度；若等待结果超时，命令仍可能已排队，应先刷新审计历史再决定是否重试。

- 玩家面板首次进入或点击刷新时读取已有玩家元数据；「在线 / 离线 / 全部」和搜索均在浏览器本地完成，不会因切换筛选反复请求服务端。点「插入名称」或 `UUID` 可把目标加到光标处。
- 常用命令保存在服务端 `TeXTech/WebAE/admin-console.json`，所有 WebAE 管理员共享，最多 64 条；载入只填充输入框，不会直接执行。
- 审计最多保留 40 条，记录操作者、命令、状态、耗时和受影响数量。列表只传输输出摘要，点击查看时才按需取完整输出；每条仅保留最后 24 行、每行最多 256 字符。
- 页面没有自动玩家轮询、世界扫描或空闲 Tick 工作；玩家快照短时复用 3 秒，审计/常用命令由后台线程合并写盘。

### QQ 群机器人管理

WebAE 管理员进入「管理控制台 → QQ 群机器人」即可配置 QQ 开放平台官方机器人。该功能默认关闭，保存 AppID、ClientSecret 并启用后，服务端会主动建立 Gateway WebSocket 长连接，不要求公网 HTTPS 回调，也不需要 OneBot/NapCat 等第三方进程。

- **查询命令**：`/status`、`/players`、`/list`、`/tps`、`/memory`、`/uptime`、`/about`、`/ping`；中文的“状态/人数/谁在线/性能/内存”等同义词也可识别。命令前缀可改，群/私聊/频道入口可分别关闭。
- **AI 对话**：`/ai <问题>` 使用 WebAE 管理员配置的服务端共享 AI Profile；可开启自然语言自动对话和共享联网搜索。会话按“目标 + QQ 用户”隔离，并受轮数、过期时间和独立 AI 冷却限制；`/reset` 仅清空当前用户会话。
- **AstrBot 意图唤起（可选）**：默认关闭，WebAE 与 AstrBot 各自独立。仅当与 AstrBot **共用同一 QQ 官方 Bot** 时，在「管理控制台 → QQ 群机器人」打开「启用意图唤起」，并安装仓库 `integrations/astrbot/astrbot_plugin_textech_intent`。开启后：显式前缀优先（默认 WebAE：`webae`/`游戏`/`mc`/`gtnh`/`服务器`；AstrBot：`tt`，同时支持 `tt生图`/`tt搜索` 无空格写法）；否则命中 WebAE 命令或可配关键词走 WebAE，其余静默让给 AstrBot。两边前缀和关键词必须保持一致。
- **安全范围**：可限制群 openid、用户 openid 和 QQ 机器人管理员 openid。QQ 管理员列表只解锁机器人自身提示，不授予 Minecraft OP，也不能从 QQ 执行任意服务端命令。AI 只收到 TPS、人数、在线名称、运行时间和 JVM 内存等有界只读快照。
- **播报与公告**：可为 `group:<openid>`、`c2c:<openid>`、`channel:<id>` 配置最短 5 分钟的定时状态播报；管理员也可手动发送公告/测试消息。所有 HTTP、AI 和 QQ 发送均进入有界后台队列，不阻塞 Tick。
- **游戏内人工消息**：OP 可用 `/textech web qq send [group|c2c|channel] <openid> <信息>` 入队消息；`/textech web qq status` 查看连接/队列，`restart` 触发异步重连。成功只代表入队，不代表 QQ 最终送达。
- **运维**：状态页显示连接阶段、自动重连时间、收发/AI/失败/丢弃/限流计数、队列深度与短期内存审计日志。ClientSecret 加密保存在服务端，页面只显示掩码；删除密钥会同时停用机器人。

群 openid、用户 openid 或频道 ID 可复用「设置 → 自动化告警 → QQ 官方机器人 → 获取目标 ID」短时监听工具。QQ 开放平台仍需给机器人开通对应事件权限；群消息通常要求成员 @机器人，主动播报受平台权限与频率限制。

### 游戏窗口截图与分享

- 在「控制」中绑定 **截取当前游戏窗口**，默认 F10。截图直接读取 Minecraft 帧缓冲，因此世界画面和当前 GUI 都会出现；它不会调用桌面截图，不会截取其他窗口。
- 截图先保存在客户端 `<实例>/TeXTech/Screenshots/`，不会自动上传。`/admscreenshot list [页]` 列历史，点击条目或执行 `preview [序号]` 可在游戏内预览，序号 1 为最新。
- `/admscreenshot send web [序号] [说明]` 将指定截图发布到 WebAE 聊天；网页使用已登录 Token 鉴权加载图片，点击图片可预览原图。
- `/admscreenshot send qq <群 openid> [序号] [说明]` 通过已配置的 QQ 官方机器人发往群聊，需要 Minecraft OP。QQ 群/C2C 图片可用，频道图片不支持。
- 默认最大 1920×1080、JPEG 质量 88%、单图 2048 KiB、每 tick 一个 24 KiB 分片、每玩家 15 秒上传冷却。管理员可用 `[webConsole] screenshot*` 配置清晰度、带宽、并发和两端保留量。服务端处理为单线程有界队列，没有空闲 Tick 扫描。

### 移动端与 PWA

内置 `manifest.webmanifest`，窄屏下自动调整侧栏与表格布局。可将控制台「添加到主屏幕」以便手机查看存储/GT/拓扑（仍建议通过 SSH 隧道访问，勿直接暴露公网）。

### 仪表盘、聊天与设置

- **AI 与 API**：服务器共享与本浏览器分 Tab。共享侧仅管理员可维护有序多 profile 与联网搜索（引擎对齐游戏内：auto / tavily_keyless / duckduckgo / tavily / brave / serper / searxng），Key 以 AES-GCM 保存在 `TeXTech/WebAE/`。个人侧任意登录用户可为当前浏览器保存多条配置到 `localStorage` 并直连 Provider；Key 不进入 WebAE API。两侧都开时可选优先来源；启用多条配置时按列表顺序对供应侧错误故障切换。两种模式都要求 Provider Base URL 使用 HTTPS（本机回环可用 HTTP），并在非 HTTPS、非回环页面禁用 Key 输入。

- **仪表盘**：GridStack 拖拽布局，**141** 套配色 + **36** 种布局 + **138** 种页面样式。设置 → 外观的“主题工作室”现有 28 个完整设计包，默认进入「顶级精选」，也可按系列筛选、关键词搜索或收藏后自由混搭四个外观轴。新增 8 套媒体科技旗舰：英雄联盟海克斯科技、星际争霸人族/神族、死亡搁浅 BRIDGES、EVA NERV/MAGI、攻壳机动队公安九课、尼尔寄叶与 TRON 光网格；均以原创 CSS 构图表达参考作品的材质、信息层级与动效语言，不内置作品图片或外部字体。原有罗德岛、赛博、航天、Printstream、Auraeco 与 GTNH/GregTech 系列继续保留，全部装饰不裁切正文或部件内容。
  - **动效性能档**：低性能主机保留静态构图但关闭持续动画/模糊；现代办公电脑启用微交互与适量玻璃；游戏主机·全特效启用扫描、轨道、粒子、辉光和图表持续动效。系统开启“减少动态效果”时会自动停用动画。
  - **分组容器（nested grid）**：可添加「分组」组件，把多个子组件收进同一格内整组拖动；编辑模式下点分组标题旁 `+` 向组内添加子组件。
  - **布局/资讯组件**：文本便签、分隔占位、告警摘要、合成队列；编辑模式下可用组件库一键添加，并使用组件右上角删除按钮移除。删除由 React 状态统一管理，不再让网格引擎直接删除页面节点。
  - **组合监控组件**：网络健康核心（综合存储/电力/合成/GT/服务器/告警）、电力流向、存储矩阵、GT 机群、玩家在线舱、告警与合成活动流、服务器生命体征（TPS/MSPT/运行时间）。这些组件只复用现有 WebAE 快照与轮询结果，不增加服务端 Tick 任务。
  - **编辑恢复**：编辑模式下支持撤销/重做（按钮或 Ctrl+Z / Ctrl+Y）；清空全部组件后刷新仍保持空布局；Storage/CPU Overview 组件高度固定为 2 行。
  - **锁定与自适应**：单组件可锁定位置/禁止拖缩、开启「按内容自适应高度」；统计卡/仪表可设告警阈值（超限高亮）。
  - **数据表列与钉选**：编辑数据表组件时，「显示列」会分别控制图标、名称、数量、注册名及各数据源专属字段；「名称」显示物品显示名，「注册名」单独显示物品注册名。`columns` 缺失或为 `null` 表示采用数据源默认列，`columns=[]` 表示明确隐藏全部列，渲染、导入和导出都不会擅自补回；切换数据源会清除旧来源的列并采用新来源默认值。钉选框聚焦即可从当前库存候选中选择，也可按显示名、注册名或物品 ID 搜索；达到服务端下发的单组件上限时需先移除旧钉选。
  - **整页导出到游戏显示器**：工具栏按钮发布当前仪表盘并复制 `textech-webae-display-binding` live 绑定；发布失败时可退到 `textech-webae-display-snapshot` 静态快照。同时把**浏览器当前视口**截成 JPEG 推送到主机（帧源 `browser-jpeg`，与网页所见一致）。保持该 WebAE 页签打开时可近似直播刷新。游戏里「WebAE面板」从剪贴板导入即可。无浏览器推帧时，主机可用 Chrome/Edge 无头截 `/embed/dashboard` 作兜底（`spa-jpeg`）；再失败才可能落到 `server-html`。安装 montoyo MCEF（1.7.10→0.6，https://montoyo.net/wd3/?modid=mcef ；玩法放 `mods/`）且 `webSurfaceUseMcef=true` 时客户端可优先本机真浏览器（`mcef`；注意官方称 1.10.2 前可能不兼容新版启动器）。`browser_not_found` 时可配 `webDisplayChromePath` / `WEBAE_CHROME_PATH`。青色空框表示尚无 JPEG。不会静默改成 AWT 快照。仅离线/未登录发布失败时才得静态快照。绑定尽量带 Origin；不含 Token/密钥。`GET /api/display/{id}/frame-status` 可查 `hasFrame`/`source`/`error`；`POST /api/display/{id}/frame` 接收浏览器 JPEG。
  - **共享组件语义导出**：组件导入/导出区可复制 `textech-monitor-widget-bundle` v1，按当前 Dashboard 顺序收集 `statCard`、`progressBar`、`gauge`、`lineChart`、`barChart`、`pieChart`、`dataTable`，单包最多 36 个；同一个「从 JSON 导入」入口可重新导入该 bundle。`radarChart`、网络健康和活动流等 WebAE-only 复合组件不会进入语义 bundle，需要在游戏内显示时继续使用整页 live/snapshot surface。
- **聊天**：侧栏 💬 进入；网页消息以 `[Web] <玩家名>: 内容` 广播到游戏内。游戏客户端显式发送的截图显示为带说明、尺寸和体积的图片消息；被服务端保留策略清理后会显示附件已失效。
- **导航栏**：边缘按钮循环展开 → 折叠 → 隐藏三态。
- **顶栏**：连接点旁显示刷新倒计时/状态。仪表盘页的全屏按钮进入 **仅仪表盘演示模式**（隐藏侧栏与顶栏，只保留网格），便于对照游戏内显示器画面。
- **浏览模式**（设置 →「浏览模式」）：仪表盘、Storage/CPU 概览、电力和拓扑等只读页面隐藏布局设置、编辑与采集按钮，保留查看、搜索、筛选、刷新和导出。除管理员与设置页外，页面外层固定适配浏览器视口；内容确实超过空间时仍可用滚轮/触摸在页面内部滚动，但不显示网页最右侧滚动条。该偏好保存在 `localStorage.webae_browsing_mode`，并包含在 UI 备份/恢复中。
- **备份与恢复**（设置 →「备份与恢复」Tab）：
  - **导出 JSON**：一次性备份主题、浏览模式、各页面布局（主仪表盘 / Storage·CPU·Power 概览 / 拓扑 / 任务书 / 配方 / 聊天等）、刷新与 Debug 偏好；可选包含 Preset 列表与服务端数据（收藏、下单模板；告警规则需 OP）。
  - **导入 JSON**：预览将覆盖的部分，支持合并模式；导入后建议刷新页面使 GridStack 布局完全生效。
  - **恢复整合包默认**：重新应用服务端 `ui-defaults.json`（实例 `TeXTech/WebAE/ui-defaults.json` 优先，否则模组 jar 内置）。
- **整合包作者**：在 WebAE 配好 UI 后导出 JSON，放到实例 `TeXTech/WebAE/ui-defaults.json`，或交给 Agent 写入模组 `assets/textech/webae/ui-defaults.json`；新玩家首次打开（无已有浏览器偏好）会自动应用。OP 亦可用 `/textech web defaults install <路径>` 安装。

## 6. 注意事项

- **默认仅本机访问**：`bindAddress=127.0.0.1` 确保只有本机浏览器能访问
- **局域网访问风险**：改 `0.0.0.0` 后局域网内持有 Token 的设备均可访问，请配合防火墙或 SSH 隧道
- **强制认证**：所有 `/api/` 端点都需要 Token；强制刷新等管理员操作额外要求 OP/admin grant
- **多层权限**：管理员可停用玩家账号（立刻回登录页，提示联系管理员）、停用单个 AE 网（含网主，游戏内 AE 不受影响）、或限制访客只能访问部分网
- **Token 安全**：主人 Token 可在授权范围内读写；访客 Token 只读且受 network allowlist 限制。请妥善保管 Token，泄露后立即撤销。
- **配方需上传并获取**：OP `/textech web recipes upload` 后，各玩家在网页配方页点「获取配方」同步到浏览器 IndexedDB
- **图标上传**：OP 执行 `/textech web icons upload [packName]`；首次加载网页会自动选择服务端记录的最近 pack
- **reload 限制**：`/textech web reload` 不重载 web 服务器监听参数；Token 与运行时数据文件不受影响
