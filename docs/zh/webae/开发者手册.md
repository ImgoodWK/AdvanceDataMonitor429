## 1. 概述

WebAE 控制台是 TeXTech 模组内嵌的 **浏览器可访问** HTTP 管理面板。玩家可以通过任意现代化浏览器，实时查看服务器端的 AE2 存储状态、电力/蒸汽消耗速率、GT 机器运行情况、搜索 NEI 配方、编辑 AE2 样板，以及批量提交 AE2 合成订单。

技术栈：
- **服务端**: NanoHTTPD 轻量级 HTTP 服务器，嵌入 Minecraft 服务端进程
- **前端**: React 18 + TypeScript + Ant Design 5 单页应用（SPA），Vite 5 构建，内联 SVG 图表（`ChartTrendSvg` 等），通过 Fetch API 调用 REST 接口；完全离线打包（无 CDN 依赖）
- **渲染**: MVC 模式，后端只返回 JSON，所有 UI 由浏览器端 React 渲染

## 2. 架构总览

```
浏览器 (React + Ant Design + 内联 SVG 图表)
    ↓ HTTP REST API (JSON, Bearer Token)
[ NanoHTTPD 服务 ]
    ↓ CountDownLatch 主线程采集
[ HandlerTick 任务队列 ]
    ↓
[ AE2 API / GT API ]
```

核心数据流：

1. **HTTP 请求进入**：NanoHTTPD 工作线程解析 URL/method，经 `WebApiRouter` 分发到对应的 handler
2. **主线程数据采集**：所有需要访问 Minecraft 世界状态的操作（AE2 网络查询、GT 机器状态读取、样板注入等）通过 `CountDownLatch` 阻塞 HTTP 线程，将任务提交到 `HandlerTick` 主线程任务队列，完成后唤醒 HTTP 线程返回结果
3. **快照缓存**：高频轮询的存储/电力数据通过 `SnapshotScheduler` 定时在主线程采集后缓存，HTTP 请求直接读取缓存，避免每次阻塞主线程

**调试开关**：`[debug] debugWebae`（默认 false，由 `ConfigDebugLoader` 加载）控制 WebAE 诊断日志，目前用于 `NeiRecipeCollector` 配方采集阶段输出 handler 数量、numRecipes 总和与过滤前后配方数，便于排查「配方搜索无结果」类问题。

## 7. 线程模型

核心挑战：Minecraft 服务端逻辑 **必须在主线程执行**，但 NanoHTTPD 在独立工作线程中处理 HTTP 请求。

解决方案：**CountDownLatch 主线程调度模式**

```java
// 伪代码示例
public SnapshotResult getSnapshot() {
    CountDownLatch latch = new CountDownLatch(1);
    SnapshotResult[] result = new SnapshotResult[1];

    HandlerTick.enqueueServerTask(() -> {
        result[0] = collectSnapshot();  // 在主线程采集
        latch.countDown();
    });

    latch.await(timeout, TimeUnit.SECONDS);
    return result[0];
}
```

三类采集策略：

| 策略 | 适用场景 | 阻塞 HTTP 线程？ |
|------|---------|-----------------|
| **缓存直读** | 存储快照、电力快照（`SnapshotScheduler` 定时采集） | 否 |
| **主线程实时查询** | 单次配方搜索、订单提交、样板注入 | 是（≤5 秒超时） |
| **客户端上传** | 配方数据（`PacketWebRecipeUpload` C→S） | 直接写入服务端缓存 |

`CountDownLatch` 超时默认 5 秒，超时后返回 HTTP 503。

## 8. 安全模型

- **Token 认证**：每位玩家一个随机 UUID，持久化到 `TeXTech/WebAE/web-tokens.json`（重新签发替换旧 Token）。TTL 可选，由 `tokenLifetimeHours` 控制（0=永不过期）
- **强制认证**：所有 `/api/` 端点都需要 `Authorization: Bearer <token>`，无关闭配置。401 响应带 `code` 字段（`missing_token`/`invalid_format`/`empty_token`/`token_expired`/`invalid_token`）
- **管理员专用端点**：`POST /api/refresh`、`/api/refresh/batch`、`/api/power/refresh`、`/api/power/refresh/batch`、`/api/gt/machines/refresh`、`/api/gt/machines/refresh/batch` 要求 OP 等级 >= 2（由 `WebAuthOpCheck` 校验）；非 OP 返回 403 + `code:admin_required`
- **默认本地绑定**：`bindAddress=127.0.0.1` 仅允许本机浏览器访问
- **无 HTTPS**：NanoHTTPD 不提供 TLS。局域网使用时通过 SSH 隧道或反向代理提供加密
- **Token 管理**：`/admweb issue`（自己）、`/admweb revoke [玩家]`（自己/OP）、`/admweb list`（OP）、`/admweb refresh [网络]`（OP，阶段 1.2）
- **不存储密码**：用户只需 Token 即可访问，不需要 Minecraft 账号验证

**安全警告**：
- `bindAddress=0.0.0.0` 会将控制台暴露给局域网所有设备，任何持有 Token 的人可查看存储、提交合成
- 建议在服务器防火墙层面限制端口访问

配方上传流程：
1. 客户端 `KeyBindings.uploadNeiRecipes(scope, snapshotItemIds)` 混合采集：`NeiRecipeCollector`（主线程；`deep` 启用物品驱动扫描）或 `RecipeSnapshotCollector`（`snapshot` 范围）+ `GameRecipeCollector`（后台），去重合并（NEI 优先）为**单次会话**

3. `RecipeUploadThrottler` 按 `recipeUploadBatchesPerTick` 节流客户端上传；经 `RecipeUploadBatcher` 按 FML 32KB 上限安全分片（默认 JSON ≤ ~32KB−512B，超大配方自动裁剪 grid/rawJson）
4. 服务端 `RecipeCacheStore.ingest()` + 末批 `rebuildHandlerCounts()`；异步去抖保存到 `web-recipes.json.gz`
5. 客户端 `RecipeLocalExporter` 同步写入 `<实例根>/TeXTech/WebAE/web-recipes.json.gz`（与服务器 gzip schema 相同）
6. 全部完成后发送 `PacketWebRecipeUploadAck` 确认

图标上传流程：
1. 客户端 `IconRenderer`（@SideOnly CLIENT）每帧离屏渲染若干物品为 32×32 PNG
2. 打包为 IconBundle（itemId → base64PNG），通过 `PacketWebIconUpload` 分片上传
3. 服务端解码写盘到 `TeXTech/WebAE/icons/<packName>/`，调用 `IconStore.recordDefaultPack` 记录最近上传 pack
4. `PacketWebIconUploadAck` 回传进度

命令触发上传流程（ID 30）：
1. OP 玩家执行 `/admweb recipes upload` 或 `/admweb icons upload`
2. `CommandWebConsole` 校验 OP（`canUseOpCommands`）与玩家身份，发送 `PacketWebUploadTrigger`（S→C，字段 uploadType=recipes/icons、packName）
3. 客户端 handler 调用 `KeyBindings.uploadNeiRecipes()` 或 `KeyBindings.triggerIconUpload(packName)` 这两个 public static 入口
4. 后续走与命令相同的上传链路（ID 26/28）

详见 `network-packets.mdc`。

### 11.1 存储监控

- **Handler**: `StorageHandler.java`（全量快照）、`StoragePagedHandler.java`（cursor 分页）
- **采集器**: `AeSnapshotCollector.java` 在主线程读取 AE2 网络存储统计
- **缓存**: `SnapshotCache` TTL = `webRefreshIntervalMs * 3`（容许采集抖动）；`snapshotVersion()` 供 cursor 失效检测
- **调度器（阶段 1.2）**: `SnapshotScheduler` 每 `refreshIntervalMs` 采集一次，分摊到多个 tick（每 tick 处理 `ceil(activeKeys / N)` 个，`N = intervalMs / 50`），只采集最近 2 分钟活跃的网络
- **返回数据**: items / fluids / essentia / bytes used+max / 合成 CPU（`CpuEntry` 含坐标、监视器位置、remainingItems/startItems 等，Phase 3 扩展）
- **端点**: `GET /api/storage`（只读缓存，未命中返回上次快照）、`GET /api/storage/batch`、`GET /api/storage/items|fluids|essentia`（cursor 分页，默认 limit=200，sort=`amount_desc|amount_asc|name_asc|name_desc`，search 过滤；409 `cursor_stale`）、`POST /api/refresh`（管理员）、`POST /api/refresh/batch`（管理员）
- **前端**: 存储页物品/流体/源质 Tab 使用 `useStoragePaged` + `VirtualStorageTable`（`@tanstack/react-virtual` 行虚拟化 + 无限滚动）；搜索 300ms 防抖；排序切换重置 cursor；合并模式 ≤3 网络客户端 merge，>3 网络提示切换单网；顶部 `OverviewWidgetGrid` 使用分页 API 的 `totalEstimate`/`totalAmountSum` 计数（`OverviewSnapshot.itemCount` 等覆盖字段）；`useSnapshotData` 切换网络时 stale-while-revalidate（保留 per-network 缓存 + `refreshing` 指示）。CPU 独立菜单见 [11.14](#1114-存储总览可配置与-cpu-独立页面phase-3)

### 11.2 电力监控

- **数据来源**: `WirelessPowerQuery` / `WirelessSteamQuery`（复用 AI 助手电力查询接口）
- **端点（阶段 1.2）**: `GET /api/power`（只读缓存）、`GET /api/power/batch`、`POST /api/power/refresh`（管理员，仅清缓存，下一采样 tick 重填）、`POST /api/power/refresh/batch`（管理员）
- **返回数据**: 当前 EU/蒸汽量、输入/输出速率、EU/蒸汽历史数组
- **前端**: 电力页全页可配置 GridStack（`PowerWidgetGrid` + `PowerWidgetContent`，持久化 `webae_power_config`）；默认含 EU 仪表、入/出率 statCard、蒸汽 progressBar、双序列 SVG 趋势 lineChart、蒸汽入/出 statCard；多网络 split 用 Tabs 切换单网络快照（见 [11.15](#1115-电力页可配置与防闪烁phase-4)）

### 11.3 GT 机器监控

  - **合并模式**：`groupByPrimaryOutput()` 按主产物 registryName 分组；`RecipeMergedCard` 显示配方类型数量徽标，弹窗内 Tabs 切换不同 handler

- **前端**（`pages/AeOrdering.tsx`，Phase 7）:

### 11.26 世界地图视图（三源采集 / 客户端快照 / SP 直读）

- **默认模式** `worldMapSnapshotMode=client_only`：**服务端不渲染**地形/AE 瓦片；多人服由同意 upload 的**玩家客户端**按优先级逐块采集并上传快照（`TeXTech/WebAE/map-snapshots/{owner}/{network}/v{n}/`）。
- **三源采集链**（`worldMapSnapshotSourcePriority`，默认 `dynmap,journeymap,client_gl`，仅 `textech.cfg` 可改）：**逐 chunk 降级**——有 Dynmap 用 Dynmap，否则 JourneyMap，再否则客户端 GL。Manifest `source` 为单源 id 或 `mixed`；`sourceStats` 记录各源 chunk 数。
  - **Dynmap（客户端）**：先裁剪本地 `dynmap/web/tiles/`；缺失时 HTTP GET `{dynmapBaseUrl|worldMapDynmapClientFetchUrl}/tiles/{world}/flat/{z}/{x}_{y}.png`（每 tick 最多 1 次 HTTP）。
  - **JourneyMap**：读 `journeymap/data`（`WorldMapJourneyMapFsReader` 供 SP 服务端直读复用）。
  - **GL 兜底**：使用 job `tilePx` 对应质量档，不再固定 `worldMapClientFallbackQuality=low`。
- **AE 透视层**：快照 upload 与 SP 直读均走客户端 `WorldMapAeVectorOverlayRenderer`（拓扑 placement + **设备 block 顶面纹理 category-ID 栅格化**；线缆/附件线宽 `worldMapAeCableWidthBlocks` 默认 0.25 方块）。服务端 legacy 路径 `WorldMapAeOverlayRenderer` 对 air-block 设备使用 dot marker，有实体 block 按顶面纹理 rasterize 类别 ID。
- **瓦片拼接（前端）**：西北角锚定 + `WORLD_MAP_TILE_FLIP_Y`（`scaleY(-1)`，仅翻转南北）；单元测试见 `worldMapTerrain.test.ts`。
- **AE 透明度（前端）**：`worldMapAeOverlayOpacity`（**0–1**）仅写入 AE 着色像素 alpha；层间 `isolation` + AE `mix-blend-mode: normal`；re-tint 保留旧图直至新图就绪。
- **快照保留**：服务端/客户端仅保留 **current + previous** 两版；瓦片 API 与 IndexedDB 支持上一版回退。
- **单人直读**（`worldMapSpDirectServe=true`）：集成服快照缺失时，`GET /api/worldmap/tiles` 直读本地 Dynmap/JM 或经 `PacketWorldMapDirectCaptureRequest/Response`（ID 45/46）触发客户端 GL；响应头 `X-WorldMap-Tile-Status=direct`、`X-WorldMap-Tile-Source=...`；短 TTL 内存缓存 `worldMapSpDirectCacheTtlSec`。
- **前端**：统一 `TopologyWorldMapView` 快照 chunk 瓦片；已移除 Leaflet Dynmap 地形视图（「在 Dynmap 中打开」外链按钮保留）。Meta 只读暴露 `snapshotSourcePriority`、`snapshotSourceStats`、`spDirectServe`。
- **更新触发（仅手动）**：Web 工具栏 **「更新地图快照」** → `POST /api/worldmap/snapshot/request`（切换 Tab/刷新不会自动重复请求）；游戏内 `/admweb wm up` 或 `/admweb worldmap upload`；附近玩家聊天可点击 **接受/拒绝** 或 `/admweb wm y`。pending 请求去重，同一网络不会重复刷屏 Offer。请求冷却 `worldMapSnapshotCooldownMs`（默认 10 秒）。
- **网络包**：37–46（含 SP 直读 45/46）；详见 `network-packets.mdc`。
- **Legacy**：`worldMapSnapshotMode=legacy` 恢复旧服务端渲染 + Dynmap 桥接；`client_only` 下 `WorldMapTerrainFallback` 服务端 Dynmap 裁剪不参与快照。
- **Dev 依赖**：`dependencies.gradle` 以 `devOnlyNonPublishable` 引入 JourneyMap 5.2.18 与 **GTNH-Web-Map (GWM) 0.4-beta-1**（GTNH 版 Dynmap）；仅 `runClient`/`runServer` 生效，发布 jar 不捆绑。

## 13. 调试与故障排查

| 问题 | 可能原因 | 检查 |
|------|---------|------|
| 启动后 `localhost:8090` 无响应 | `enabled=false` | 检查 `config/textech/textech.cfg` `[webConsole] enabled` |
| 端口占用 | 其他服务占用 8090 | 修改 `port` 配置 |
| 认证失败 (401) | Token 过期或被撤销 | 运行 `/admweb issue` 重新生成；查看 `code` 字段（`token_expired` vs `invalid_token`） |
| 刷新返回 403 | 非 OP 调用管理员刷新 | 改用游戏内 `/admweb refresh` |
| 存储/电力短暂为空 | 缓存冷启动 | 等待一个 `refreshIntervalMs` 周期；调度器只采集活跃网络 |
| 存储/电力持续为空 | AE2 网络未连接或无活跃网络 | 打开网页控制台/选择网络，让 `SnapshotScheduler.markActive` 运行 |
| 配方搜索无结果 | 未上传 / 用了 displayName 做精确搜索 / 缓存为空 | 执行 `/admweb recipes clear` 后 `/admweb recipes upload snapshot`（日常）或 `upload`（全量 NEI+Game）；Web 端默认模糊搜索或从补全选择 registry；开启 `[debug] debugWebae=true` 查看 NEI 采集日志 |
| 图标显示为文字缩写 | 认证失败 / pack 名不一致 / itemId 格式不匹配 | v3.0 已修复：`WebAuthMiddleware` 支持 `?token=` query 参数回退，前端 Icon 组件自动拼接 token；确认 `AeSnapshotCollector` 用 registry name；检查 `TeXTech/WebAE/icons/default-pack.txt` |
| 聊天消息不显示 | 未上传或 Token 无 playerUuid | 确认 `ChatMessageStore` 已持久化 `web-chat.json`；检查 `/api/chat/since` 响应；游戏内消息需 `sendChatMsg` 广播 |
| 玩家头像回退首字母 | 离线模式或 GameProfile 无 textures | `SkinUrlResolver` 对离线玩家返回 null 属正常；正版玩家检查 GameProfile textures property |
| CountDownLatch 超时 (503) | 主线程过载 | 增大超时参数或检查 `HandlerTick` 任务积压 |
| GT 机器列表为空 | `GtCompat` 未启用 | 检查是否安装了 GTNH GT 模组 |
