## 1. 先理解四个东西

| 名称 | 作用 | 当前项目中的位置 |
|------|------|------------------|
| WebAE 后端 | Minecraft/Forge 内运行的 HTTP API 和内嵌网页 | `127.0.0.1:8090` |
| Vite 前端 | 开发模式网页，改 TSX 后即时刷新，并代理 API 到 8090 | `localhost:5174` |
| 浏览器 MCP | 让新 Agent 打开网页、点击、截图和检查页面 | 建议使用 `@playwright/mcp` |
| WebAE Token/登录码 | 证明浏览器是谁、能访问哪些网络 | 游戏内 `/textech web ...` 命令签发 |

它们的关系：

```text
Codex Agent -> Playwright MCP -> http://localhost:5174
                                  |
                                  +-- Vite proxy -> http://127.0.0.1:8090/api
                                                        |
                                                        +-- Minecraft/Forge + TeXTech
```

MCP 不会自动启动 Minecraft，Token 也不会自动启动服务；三部分都准备好才能做真实浏览器验收。

## 3. 一次性配置浏览器 MCP

### 3.1 最简单的安装方式

打开 PowerShell，执行：

```powershell
codex.cmd mcp add playwright -- npx.cmd -y @playwright/mcp@latest
```

说明：

- `codex.cmd`：绕过 Windows 对 `codex.ps1` 的执行策略阻止，不修改系统策略。
- `mcp add playwright`：给服务器取一个稳定名字。
- `--`：后面的内容是启动 MCP 的命令。
- `npx.cmd -y`：需要时从 npm 获取并启动包。
- `@latest`：安装时取当前稳定版本。需要完全可重复时，把它改成已经验证的固定版本，例如 `@playwright/mcp@0.0.78`。

检查是否登记成功：

```powershell
codex.cmd mcp list
codex.cmd mcp get playwright
```

然后完全关闭并重新打开 Codex，再新建 Agent 窗口。正在运行的旧窗口通常不会动态获得新 MCP 工具。

### 3.2 验证 MCP，而不是直接测 WebAE

新窗口先让 Agent 做一个无 Token 的最小验证：

```text
请列出当前可用的浏览器 MCP 工具，然后打开 about:blank，创建页面快照并关闭页面。
不要访问外网，不要修改仓库。
```

不同版本暴露的工具名可能不同；以新窗口实际列出的工具为准，不要强行套用 Cursor 的 `browser_lock` 名称。

### 3.3 卸载或重装

```powershell
codex.cmd mcp remove playwright
codex.cmd mcp add playwright -- npx.cmd -y @playwright/mcp@0.0.78
```

如果首次启动一直停在 npm 下载：

1. 确认浏览器能打开 `https://registry.npmjs.org/`。
2. 检查代理、杀毒软件和 `%LocalAppData%\npm-cache` 写权限。
3. 先运行 `npm.cmd view @playwright/mcp version` 验证 npm 连接。
4. 再执行上面的固定版本注册命令。

不要通过 `Set-ExecutionPolicy Unrestricted` 解决 `codex.ps1` 问题；使用 `codex.cmd` 更小、更安全。

### 3.4 Cursor MCP 与 Codex MCP 的区别

仓库 `.cursor/mcp.json` 中有 `textech-doc-check`、`textech-webae-api`、`textech-admweb`、`textech-build`，但它是 Cursor 配置，不会自动注册到 Codex。

浏览器验收只强制需要 Playwright MCP。项目 MCP 是可选增强，不能替代浏览器：

- `textech-webae-api`：Bearer 调用 WebAE 只读 API。
- `textech-admweb`：脱敏读取本地配置/Token 元数据。
- `textech-doc-check`：运行文档一致性检查。
- `textech-build`：封装 Gradle/npm 命令。

后续如需给 Codex 注册项目 MCP，应使用 `codex.cmd mcp add ...` 和绝对路径，不能直接复制 `.cursor/mcp.json`。先让新 Agent读取对应 `tools/mcp/*/README.md`，逐个注册和验证。

示例，只注册只读 WebAE API MCP，不把 Token 写进 Codex 配置：

```powershell
codex.cmd mcp add textech-webae-api `
  --env WEBAE_INSTANCE_ROOT=D:\gtnhcode\AdvanceDataMonitor429\run `
  -- cmd.exe /c `
  D:\gtnhcode\AdvanceDataMonitor429\tools\mcp\run-server.cmd `
  D:\gtnhcode\AdvanceDataMonitor429\tools\mcp\webae-api-server\server.py
```

该 MCP 会从本地实例 Token 文件寻找 owner Token。不要添加 `WEBAE_REVEAL_TOKENS=1`，也不要把 `WEBAE_TOKEN=<明文>` 固化到全局 MCP 配置。

## 4. 启动 WebAE：小白推荐路径

### 4.1 方式 A：单人开发世界，最简单

适合先把浏览器联调跑通。

终端 1，在项目根目录运行：

```powershell
.\gradlew.bat runClient
```

等待 Minecraft 打开后：

1. 进入一个测试用单人世界。
2. 确认世界中存在并加载至少一块高级数据监视器；主人 Token 依赖它发现 AE 网络。
3. 在聊天中执行 `/textech web server status`。
4. 若显示未启动，确认 `run/config/textech/textech.cfg` 的 `[webConsole]` 为：

```ini
[webConsole]
enabled=true
port=8090
bindAddress=127.0.0.1
```

`enabled`、`port`、`bindAddress` 变更需要退出并重新启动游戏/服务端，仅执行 reload 不够。

### 4.2 方式 B：独立服务端，更接近正式环境

终端 1：

```powershell
.\gradlew.bat runServer
```

终端 2：启动客户端并连接测试服务端：

```powershell
.\gradlew.bat runClient --username=WebAeTester
```

第一次联调不必从方式 B 开始。先用方式 A 验证页面和 MCP，再做独立服务端权限、多人和重启测试。

### 4.3 检查 8090

不要凭感觉判断服务是否启动，另开 PowerShell 执行：

```powershell
Test-NetConnection 127.0.0.1 -Port 8090
```

看到 `TcpTestSucceeded : True` 才表示后端监听成功。也可以打开：

```text
http://127.0.0.1:8090
```

首页能出现登录界面即可；访问 `/api/*` 返回 401 在没有 Token 时是正常现象。

## 5. 启动 Vite 开发前端

终端 2 或 3：

```powershell
Set-Location D:\gtnhcode\AdvanceDataMonitor429\webae-frontend
npm.cmd install
npm.cmd run dev
```

本机已经存在 `node_modules`，日常可以直接运行 `npm.cmd run dev`；只有 lockfile/依赖变化或提示缺包时再执行 install。

看到 Vite 输出后检查：

```powershell
Test-NetConnection 127.0.0.1 -Port 5174
```

开发浏览器地址：

```text
http://localhost:5174
```

为什么推荐 5174：

- TSX/CSS 改动可以热更新。
- `/api` 自动代理到 8090。
- 不需要每次前端修改都先构建内嵌资源。

什么时候使用 8090 内嵌页：正式构建完成后，验证游戏实际打包资源。此时必须先运行 `npm.cmd run build`，再访问 `http://127.0.0.1:8090` 并硬刷新。

## 6. 获取并安全使用 Token

### 6.1 首次登录推荐：一次性 6 位码

在游戏聊天中执行：

```text
/textech web login
```

它会生成一个 5 分钟有效、只能用一次的 6 位登录码。打开 `http://localhost:5174`，在登录页手动输入。这是浏览器冒烟最推荐的方式，因为不需要把长期 Token 放进 URL、Agent 对话或截图。

### 6.2 主人 Token

需要测试完整 owner 功能时，在游戏中执行：

```text
/textech web issue
```

前提：玩家至少拥有一块已加载的高级数据监视器。完整 Token 只显示一次。登录后浏览器会按设置保存到 localStorage。

不要：

- 不要把 Token 写进本计划、Git、`.env`、截图名或 Issue。
- 不要在 Agent 对话中粘贴真实 Token。
- 不要使用 `?token=<真实值>` 做日常分享链接。
- 不要让浏览器测试 trace、视频或截图包含 Token 输入框明文。

### 6.3 管理员测试

先用 owner/登录码正常登录，再由 OP 或单人作弊模式执行：

```text
/textech web admin issue browser-smoke
```

把得到的一次性 `wae-adm-*` 引导码填入 WebAE 设置页的管理员提权区域。不要使用 `--reuse`，除非专门测试可复用引导码。

测试完成后吊销：

```text
/textech web admin revoke <token|uuid|名称>
```

紧急情况下：

```text
/textech web admin rotate
```

`rotate` 会吊销全部管理员授权和未使用引导码，只用于泄露或专门的安全测试。

### 6.4 访客/角色测试

现有版本可用：

```text
/textech web guest <在线玩家名>
```

细粒度角色与 API Token 实施后，E2E 应创建专用短期 Viewer/Operator Token，并在测试结束自动吊销。迁移前不要假设 guest 已经是严格只读角色。

## 7. 让新 Agent 做第一次真实冒烟

确认 8090、5174 都监听，浏览器 MCP 已在新 Codex 窗口出现后，发送：

```text
请按 docs/zh/webae/浏览器联调环境配置计划.md 做只读浏览器冒烟。

目标 URL：http://localhost:5174
登录：先停在登录页，由我手动输入一次性 6 位登录码；不要让我把长期 Token 发到对话里。
范围：Dashboard -> Storage -> Recipes -> Settings -> Admin/Diagnostics。
要求：检查页面快照、控制台致命错误、主要 API 失败、桌面与 390x844 移动视口，保存关键截图结论。
禁止：下单、样板写入、任务领取、服务端命令、告警测试、QQ 发送和任何真实写操作。
结束：关闭或释放浏览器会话，汇总通过页、失败页、控制台错误和截图结论。
```

管理员页需要单独一轮：用户先在页面完成管理员引导码兑换，再授权 Agent 进行只读检查。不要让 Agent 自动尝试高风险命令。

### 7.1 最小验收矩阵

| 检查 | 期望 |
|------|------|
| 登录 | 一次性码成功，URL/截图不出现长期 Token |
| Dashboard | 非空、有明确加载/空状态、无白屏 |
| Storage/Recipes | 搜索与滚动可用，图标失败有占位 |
| Settings | 标签切换、主题预览、Token/密钥掩码正常 |
| Admin/Diagnostics | 无权限时明确拒绝；有权限时数据可见且不自动执行动作 |
| 桌面/移动端 | 无文本覆盖、按钮不可达和外层异常横向滚动 |
| 控制台 | 无未捕获异常、无限重试和连续 5xx |
| 网络 | 页面隐藏后轮询暂停策略符合预期 |

## 8. 常见故障排查

### 8.1 `codex` 提示禁止运行脚本

现象：`codex.ps1` cannot be loaded / PSSecurityException。

处理：

```powershell
codex.cmd mcp list
```

不要修改全局 PowerShell 执行策略。

### 8.2 `codex.cmd mcp list` 没有 playwright

重新执行注册命令，确认没有报错，然后完全重启 Codex。仍失败时：

```powershell
codex.cmd mcp get playwright
codex.cmd mcp remove playwright
codex.cmd mcp add playwright -- npx.cmd -y @playwright/mcp@0.0.78
```

### 8.3 8090 connection refused

依次检查：

1. 是否已经进入单人世界，或 `runServer` 是否完成启动。
2. `/textech web server status` 输出。
3. `run/config/textech/textech.cfg` 是否 `enabled=true`。
4. 修改 enabled/port/bind 后是否真正重启。
5. 8090 是否被其他程序占用：

```powershell
Get-NetTCPConnection -LocalPort 8090 -ErrorAction SilentlyContinue
```

### 8.4 5174 connection refused

确认 Vite 终端仍在运行，并在 `webae-frontend/` 执行的是：

```powershell
npm.cmd run dev
```

### 8.5 页面能开但 API 401

- 6 位码已过 5 分钟或已经使用：重新 `/textech web login`。
- Token 已撤销/过期：重新 `/textech web issue`。
- 自动登录保存了旧 Token：在登录/设置页退出或更换 Token，不要手改服务端 Token 文件。

### 8.6 页面数据为空

- 确认高级数据监视器所在区块已加载。
- 确认监视器连接的 AE 网络真实存在。
- 等待一次缓存采集周期。
- 不要为了“空数据”立即反复强制刷新；先看 Diagnostics 和服务端日志。

### 8.7 5174 正常、8090 内嵌页还是旧界面

Vite 热更新只作用于 5174。验证内嵌页前执行：

```powershell
Set-Location webae-frontend
npm.cmd run build
```

然后重启/刷新 8090 页面并使用 Ctrl+F5。构建只能通过 Vite 工作流生成，不能手改 `src/main/resources/assets/textech/webae/`。

## 9. 用户与 Agent 的分工

用户需要亲自做：

- 首次进入 Minecraft 世界。
- 执行签发登录码/Token/管理员引导码的游戏命令。
- 在浏览器中输入一次性登录码。
- 决定是否授权任何真实写操作。

Agent 可以做：

- 经用户允许运行 `codex.cmd mcp add`。
- 启动/停止 `runClient`、`runServer` 和 Vite 进程。
- 检查配置、端口、日志和脱敏 Token 元数据。
- 执行只读浏览器冒烟、截图和自动化测试。
- 在专用测试世界且获得明确授权后执行受控写测试。

Agent 不得做：

- 从磁盘读取并在对话中显示完整 Token。
- 把 Token 固化到仓库或全局 MCP 配置。
- 未经授权执行下单、样板写入、命令、封禁、OP、QQ/邮件发送。

## 10. 环境就绪定义

满足全部条件后，才可把“缺少浏览器 MCP、运行服务和 Token”标记为已解决：

- `codex.cmd mcp list` 能看到 playwright。
- 新 Agent 窗口实际出现浏览器 MCP 工具，并能操作 `about:blank`。
- `Test-NetConnection 127.0.0.1 -Port 8090` 为 True。
- `Test-NetConnection 127.0.0.1 -Port 5174` 为 True。
- 用户能用一次性 6 位码登录 5174。
- owner、guest/角色、admin 三种权限态各完成一次预期验证。
- Dashboard、Storage、Recipes、Settings、Admin/Diagnostics 完成桌面和移动端冒烟。
- 浏览器 trace、截图、日志、URL 和 Git diff 中没有 Token/密钥。
- 测试完成后吊销专用授权并停止不再需要的服务进程。

完成环境配置后，再按 [WebAE 下一阶段实施计划](下一阶段实施计划.md) 从阶段 0 开始实现。
